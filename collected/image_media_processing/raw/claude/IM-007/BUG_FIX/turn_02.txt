Looking at the version I gave you, the threshold is already computed dynamically — `avg = pixels.mean()` — not hardcoded to 128, so that specific bug shouldn't be present there. But since you're flagging a fixed-128 threshold, here's the explicit fix so you can diff it against whatever version has the bug (e.g. if someone wrote `bits = pixels >= 128` instead of computing the mean):

```python
from PIL import Image
import numpy as np


def compute_ahash(image_path, hash_size=8):
    """
    Compute the average hash (aHash) of an image.

    The threshold is the TRUE MEAN of the resized grayscale pixels,
    recomputed per image -- NOT a fixed constant like 128. Using a
    hardcoded threshold breaks the whole point of aHash: it would make
    the hash sensitive to brightness shifts (e.g. a uniformly brightened
    or darkened version of the same image would hash very differently),
    instead of tolerant of them.
    """
    image = Image.open(image_path).convert("L")
    image = image.resize((hash_size, hash_size), Image.LANCZOS)

    pixels = np.asarray(image, dtype=np.float64)

    # Correct: threshold = mean of THIS image's resized pixels
    avg = pixels.mean()

    # WRONG (the bug): bits = pixels >= 128
    bits = pixels >= avg

    hash_value = 0
    for bit in bits.flatten():
        hash_value = (hash_value << 1) | int(bit)

    return hash_value


def hamming_distance(hash_a, hash_b):
    return bin(hash_a ^ hash_b).count("1")
```

Why the fixed-128 version breaks brightness tolerance: if you take an image and uniformly brighten it (e.g. all pixels +50), a dynamic mean threshold shifts along with the pixels, so pixels that were above/below average stay above/below average — the hash barely changes. With a fixed threshold of 128, brightening pushes many previously-below-128 pixels to above-128 (or vice versa for darkening), flipping bits that shouldn't flip and producing a large Hamming distance between what should be near-duplicate images. Recomputing `avg = pixels.mean()` per image is what restores that invariance.

A quick way to verify the fix works: hash an image, then hash a brightness-shifted copy of it (`ImageEnhance.Brightness(image).enhance(1.3)`) and confirm `hamming_distance` stays small (single digits out of 64), rather than blowing up toward ~32 (random/uncorrelated).
