Good call — this is an important edge case. With the current code it happens to work for exact matches, but it's worth making the behavior *explicit and guaranteed* rather than relying on `round()` producing the exact same integer. Here's the updated version:

```python
import os
from pathlib import Path
from PIL import Image

def letterbox_resize(input_dir, output_dir, target_size, pad_color=(0, 0, 0),
                     align='center'):
    """
    Resize all images in input_dir preserving aspect ratio, padding to target_size.

    Args:
        input_dir (str): Directory containing input images.
        output_dir (str): Directory to save processed images.
        target_size (tuple): (width, height) of output images.
        pad_color (tuple): RGB tuple for padding. Default (0, 0, 0).
        align (str): 'center' (default) or 'top-left'.

    Behavior:
        - Scale factor = min(target_w / src_w, target_h / src_h)  (always fits).
        - If src size == target_size exactly, the image is passed through
          unchanged: no resize, no padding, no re-encode beyond format needs.
    """
    input_dir = Path(input_dir)
    output_dir = Path(output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)

    target_w, target_h = target_size
    if target_w <= 0 or target_h <= 0:
        raise ValueError("target_size must be positive (width, height)")

    valid_aligns = ('center', 'top-left')
    if align not in valid_aligns:
        raise ValueError(f"align must be one of {valid_aligns}, got {align!r}")

    valid_ext = {'.jpg', '.jpeg', '.png', '.bmp', '.webp', '.tif', '.tiff', '.gif'}

    for img_path in input_dir.iterdir():
        if not img_path.is_file() or img_path.suffix.lower() not in valid_ext:
            continue

        try:
            with Image.open(img_path) as img:
                # Normalize mode
                if img.mode in ('RGBA', 'LA', 'P'):
                    img = img.convert('RGB')
                elif img.mode not in ('RGB', 'L'):
                    img = img.convert('RGB')

                src_w, src_h = img.size
                if src_w == 0 or src_h == 0:
                    print(f"Skipping {img_path}: zero-sized image")
                    continue

                out_path = output_dir / img_path.name

                # ---- Exact-match fast path ----
                # If already the target size, skip resize + pad entirely.
                if src_w == target_w and src_h == target_h:
                    save_kwargs = {}
                    if out_path.suffix.lower() in ('.jpg', '.jpeg'):
                        save_kwargs['quality'] = 95
                        save_kwargs['subsampling'] = 0
                    img.save(out_path, **save_kwargs)
                    continue
                # --------------------------------

                # Correct scale: respect BOTH dimensions
                scale = min(target_w / src_w, target_h / src_h)

                new_w = max(1, int(round(src_w * scale)))
                new_h = max(1, int(round(src_h * scale)))

                # Hard clamp against rounding overflow
                new_w = min(new_w, target_w)
                new_h = min(new_h, target_h)

                # If after rounding we landed exactly on target, skip paste
                if new_w == target_w and new_h == target_h:
                    resized = img.resize((new_w, new_h), Image.LANCZOS)
                    save_kwargs = {}
                    if out_path.suffix.lower() in ('.jpg', '.jpeg'):
                        save_kwargs['quality'] = 95
                        save_kwargs['subsampling'] = 0
                    resized.save(out_path, **save_kwargs)
                    continue

                resized = img.resize((new_w, new_h), Image.LANCZOS)

                # Build canvas
                if resized.mode == 'L':
                    if isinstance(pad_color, (tuple, list)):
                        pad_val = pad_color[0] if len(pad_color) == 1 else sum(pad_color) // 3
                    else:
                        pad_val = pad_color
                    canvas = Image.new('L', (target_w, target_h), pad_val)
                else:
                    canvas = Image.new('RGB', (target_w, target_h), pad_color)

                # Compute paste position based on align
                if align == 'center':
                    paste_x = (target_w - new_w) // 2
                    paste_y = (target_h - new_h) // 2
                elif align == 'top-left':
                    paste_x = 0
                    paste_y = 0
                else:
                    raise ValueError(f"Unsupported align: {align}")

                canvas.paste(resized, (paste_x, paste_y))

                save_kwargs = {}
                if out_path.suffix.lower() in ('.jpg', '.jpeg'):
                    save_kwargs['quality'] = 95
                    save_kwargs['subsampling'] = 0
                canvas.save(out_path, **save_kwargs)

        except Exception as e:
            print(f"Failed to process {img_path}: {e}")

    print(f"Done. Processed images saved to {output_dir}")
```

**What changed:**

1. **Exact-match fast path** — Before any scaling math, we check `src_w == target_w and src_h == target_h`. If they match exactly, the image is written out directly with **no resize and no paste onto a canvas**. This is the strongest guarantee: the pixel data is untouched (modulo the RGB-mode normalization and JPEG re-encode).

2. **Post-rounding fast path** — After computing `new_w`/`new_h`, if integer rounding happens to land exactly on `(target_w, target_h)` (which can occur for e.g. a 1280×640 source into 640×320, or any source whose aspect ratio matches the target's), we skip the canvas creation and paste too. This avoids a redundant copy of a full-frame image onto a same-sized canvas.

3. **Consistent save path** — The JPEG quality/subsampling kwargs are now applied in all three output paths so a passthrough JPEG doesn't get a different quality than a padded one.

**Why the two fast paths matter:**

- **Semantic correctness** — "Already the target size → unchanged" is now a guarantee, not a coincidence of floating-point math.
- **Performance** — For pipelines reprocessing already-conformant images (e.g., re-running augmentation with the same target), you skip a resize + canvas allocation + paste per image. On large batches this is meaningful.
- **Avoiding subtle drift** — Even though `resize((same_w, same_h))` should be a no-op in PIL, going through LANCZOS on identical dimensions can occasionally differ by a channel value due to filter kernel math. The fast path sidesteps that entirely.

**Edge cases covered:**

| Source size | Target size | Path taken | Result |
|---|---|---|---|
| 640×640 | 640×640 | Exact-match fast path | Identical pixels, no padding |
| 1920×1080 | 640×640 | Scale + pad | Scale 0.333, 640×360, centered/top-left |
| 1280×640 | 640×320 | Post-round fast path | Scaled exactly, no pad |
| 100×100 | 640×640 | Scale + pad | Scale 6.4, 640×640, no visible pad (fills) |
| 0×100 | 640×640 | Skipped | Warning printed |

One thing to be aware of: the exact-match fast path still re-encodes the image (via `img.save(...)`), so it's not byte-identical to the source file — it's pixel-identical after decode. If you need *byte*-identical passthrough for exact matches (e.g., to preserve original JPEG bytes), that would require copying the file with `shutil.copy2` instead of decoding and re-saving, which trades off the RGB-normalization step.
