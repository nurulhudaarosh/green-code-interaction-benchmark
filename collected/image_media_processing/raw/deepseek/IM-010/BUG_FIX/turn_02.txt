You're right — here's the corrected implementation. The key fix is passing `expand=True` to `Image.rotate` so the canvas grows to fit the rotated image, preventing corner clipping before the center-crop/pad step.

```python
import os
from pathlib import Path
from PIL import Image


def rotate_and_crop(input_dir, output_dir, angle_degrees, crop_size):
    """
    Rotate each image in input_dir by angle_degrees and center-crop/pad to crop_size.

    Args:
        input_dir (str): Directory containing input images.
        output_dir (str): Directory to save processed images.
        angle_degrees (float): Rotation angle in degrees (counter-clockwise).
        crop_size (tuple): Target size as (width, height).

    Returns:
        int: Number of images processed.
    """
    if isinstance(crop_size, int):
        crop_size = (crop_size, crop_size)
    target_w, target_h = crop_size

    input_path = Path(input_dir)
    output_path = Path(output_dir)
    output_path.mkdir(parents=True, exist_ok=True)

    valid_exts = {'.jpg', '.jpeg', '.png', '.bmp', '.tif', '.tiff', '.webp'}
    processed = 0

    for img_file in sorted(input_path.iterdir()):
        if not img_file.is_file() or img_file.suffix.lower() not in valid_exts:
            continue

        try:
            with Image.open(img_file) as img:
                has_alpha = img.mode in ('RGBA', 'LA') or (
                    img.mode == 'P' and 'transparency' in img.info
                )
                work = img.convert('RGBA' if has_alpha else 'RGB')

                fill = (0, 0, 0, 0) if has_alpha else (0, 0, 0)

                # FIX: expand=True grows the canvas to fit the rotated image,
                # so no corners are clipped before cropping.
                rotated = work.rotate(
                    angle_degrees,
                    resample=Image.BICUBIC,
                    expand=True,
                    fillcolor=fill,
                )

                rw, rh = rotated.size
                left = (rw - target_w) // 2
                top = (rh - target_h) // 2

                if target_w <= rw and target_h <= rh:
                    cropped = rotated.crop(
                        (left, top, left + target_w, top + target_h)
                    )
                else:
                    src_left = max(0, left)
                    src_top = max(0, top)
                    src_right = min(rw, left + target_w)
                    src_bottom = min(rh, top + target_h)

                    region = rotated.crop(
                        (src_left, src_top, src_right, src_bottom)
                    )

                    canvas = Image.new(
                        'RGBA' if has_alpha else 'RGB',
                        (target_w, target_h),
                        fill,
                    )
                    canvas.paste(region, (src_left - left, src_top - top))
                    cropped = canvas

                out_file = output_path / img_file.name
                save_kwargs = {}
                if out_file.suffix.lower() in ('.jpg', '.jpeg'):
                    cropped = cropped.convert('RGB')
                    save_kwargs = {'quality': 95, 'subsampling': 0}
                cropped.save(out_file, **save_kwargs)
                processed += 1

        except Exception as e:
            print(f"Failed to process {img_file}: {e}")

    return processed


if __name__ == "__main__":
    n = rotate_and_crop(
        input_dir="input_images",
        output_dir="output_images",
        angle_degrees=30,
        crop_size=(256, 256),
    )
    print(f"Processed {n} images.")
```




### Why this matters

PIL's `Image.rotate` defaults to `expand=False`, which keeps the original width/height and simply maps the rotated pixels into that same frame. Any pixels that fall outside the original bounding box — most notably the corners at non-90° angles — are silently discarded *before* your center-crop runs. Even worse, this failure is silent: the crop still succeeds and produces an image of the exact requested size, so downstream code sees no error and the only symptom is missing content.

With `expand=True`, PIL computes the new bounding box that contains the entire rotated rectangle and resizes the canvas to fit it. All original pixels survive; corners are filled with `fillcolor` (transparent for alpha images, black otherwise). The subsequent center-crop then samples from a canvas that actually contains the full rotated content, so the padding regions you'd expect at the corners are what get cropped away — not real image data.

### A quick sanity check

For a 512×512 image rotated 45° with `expand=True`, the new canvas is ~724×724. With `expand=False` it stays 512×512 and roughly the outer 25% of each edge is lost. If your pipeline "worked" before but produced noticeably tighter framing or missing subject matter at the corners, this was the cause.
