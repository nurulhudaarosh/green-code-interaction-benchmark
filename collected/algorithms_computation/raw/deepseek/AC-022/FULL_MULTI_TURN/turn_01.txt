## Problem Identification and Understanding

**Problem**: Compute the **Damerau-Levenshtein distance** between two strings. This is the minimum number of edit operations needed to transform one string into another, where the allowed operations are:

1. **Insertion** — insert a single character (cost 1)
2. **Deletion** — delete a single character (cost 1)
3. **Substitution** — replace one character with another (cost 1)
4. **Adjacent transposition** — swap two adjacent characters (cost 1)

**Key constraints**:
- Operations allowed: insertion, deletion, substitution, and transposition of two *adjacent* characters.
- Each operation costs exactly 1.
- The transposition operation only applies to adjacent characters (not arbitrary swaps).
- No other operations (e.g., no block moves, no multi-character edits).
- Input strings can be of any length (including empty).

**Required output**: A non-negative integer — the minimum total cost to convert the source string into the target string.

---

## Algorithm Description

We use **dynamic programming** with a 2D table `dp[i][j]` = edit distance between the first `i` characters of `s1` and the first `j` characters of `s2`.

**Recurrence**:
- Base cases:
  - `dp[i][0] = i` (delete all `i` characters)
  - `dp[0][j] = j` (insert all `j` characters)
- For `i ≥ 1`, `j ≥ 1`:
  - `dp[i][j] = min(`
    - `dp[i-1][j] + 1` (deletion)
    - `dp[i][j-1] + 1` (insertion)
    - `dp[i-1][j-1] + cost` where `cost = 0` if `s1[i-1] == s2[j-1]`, else `1` (match/substitution)
    - **Transposition**: if `i ≥ 2` and `j ≥ 2` and `s1[i-1] == s2[j-2]` and `s1[i-2] == s2[j-1]`, then `dp[i-2][j-2] + 1`
  - `)`

**Complexity**: Time O(n·m), Space O(n·m). This is the "optimal string alignment" (restricted) version of Damerau-Levenshtein, which is the standard interpretation when only adjacent transpositions are allowed and each substring is edited at most once. (The unrestricted version, which permits a character to be edited multiple times, requires an additional check with the last occurrence of each character; the restricted version is what's typically meant by "edit distance with adjacent transposition" in textbook problems and matches the described cost model directly.)

## Python Implementation

```python
def edit_distance(s1: str, s2: str) -> int:
    """
    Compute Damerau-Levenshtein (optimal string alignment) distance between s1 and s2.
    Allowed operations (each cost 1): insertion, deletion, substitution,
    and transposition of two adjacent characters.

    Returns the minimum edit distance as a non-negative integer.
    """
    n, m = len(s1), len(s2)

    # dp[i][j] = distance between s1[:i] and s2[:j]
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    # Base cases
    for i in range(n + 1):
        dp[i][0] = i
    for j in range(m + 1):
        dp[0][j] = j

    # Fill the table
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            cost = 0 if s1[i - 1] == s2[j - 1] else 1

            best = min(
                dp[i - 1][j] + 1,        # deletion
                dp[i][j - 1] + 1,        # insertion
                dp[i - 1][j - 1] + cost  # match or substitution
            )

            # Adjacent transposition
            if (i >= 2 and j >= 2
                    and s1[i - 1] == s2[j - 2]
                    and s1[i - 2] == s2[j - 1]):
                best = min(best, dp[i - 2][j - 2] + 1)

            dp[i][j] = best

    return dp[n][m]


if __name__ == "__main__":
    # Deterministic test cases
    tests = [
        ("", "", 0),
        ("", "abc", 3),
        ("abc", "", 3),
        ("abc", "abc", 0),
        ("abc", "abd", 1),          # substitution
        ("abc", "ab", 1),           # deletion
        ("ab", "abc", 1),           # insertion
        ("ab", "ba", 1),            # transposition
        ("ca", "abc", 2),           # insertion + transposition
        ("kitten", "sitting", 3),   # classic Levenshtein example
        ("teh", "the", 1),          # single transposition
        ("a cat", "an act", 2),     # multiple operations
        ("abcdef", "abcfed", 1),    # one adjacent swap at the end
        ("abcd", "badc", 2),        # two independent transpositions
    ]

    for s1, s2, expected in tests:
        result = edit_distance(s1, s2)
        status = "OK " if result == expected else "FAIL"
        print(f"[{status}] distance({s1!r}, {s2!r}) = {result} (expected {expected})")
```

**Notes on correctness**:
- The explicit transposition transition `dp[i-2][j-2] + 1` is the only addition beyond standard Levenshtein, and it only fires when the last two characters of `s1[:i]` are the reverse of the last two characters of `s2[:j]`.
- This is the *optimal string alignment* variant, which is the standard interpretation when each adjacent transposition costs 1 and the task is the classic "edit distance with adjacent transposition." It runs in O(n·m) time and space using only the Python standard library.
