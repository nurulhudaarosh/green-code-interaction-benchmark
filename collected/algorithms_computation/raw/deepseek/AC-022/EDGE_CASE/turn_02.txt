# Edit Distance With Transposition — Restatement and Extended Handling

## 1. Original Problem Restated

**Problem.** Given two strings `a` and `b`, compute the minimum total cost to transform `a` into `b` using four operations, each costing exactly **1**:

1. **Insertion** — insert one character anywhere.
2. **Deletion** — delete one character anywhere.
3. **Substitution** — replace one character with another.
4. **Adjacent transposition** — swap two adjacent characters in `a`.

**Input:** two strings `a`, `b`.
**Output:** a single non-negative integer = the minimum total cost.

**Constraints that matter here:**
- Transposition applies only to **adjacent** characters and costs 1 (cheaper than delete+insert = 2).
- All operations are symmetric in cost, so the distance is symmetric: `d(a,b) = d(b,a)`.
- We use the **Optimal String Alignment (OSA)** variant: a substring may not be edited more than once, which makes the DP deterministic and well-defined for repeated values.

---

## 2. Explicitly Handling Repeated Values

Repeated values (duplicate characters) create ambiguity in *which* occurrence of a character to match. Two sub-problems arise:

### 2.1 Which match to choose
When `a[i-1] == b[j-1]` we must decide whether to treat it as a **match** (cost 0) or to route around it via insertion/deletion/transposition. The DP handles this by taking the **minimum** over all four transitions, so a duplicate match never forces a suboptimal path — it is always compared against the alternatives.

### 2.2 Transposition with duplicates
The transposition rule

```
a[i-1] == b[j-2]  and  a[i-2] == b[j-1]
```

is checked on **the two specific adjacent characters** at positions `i-2, i-1` in `a` and `j-2, j-1` in `b`. When characters repeat, several transposition opportunities can exist; the DP examines the one anchored at the current cell and relies on earlier cells (`dp[i-2][j-2]`) having already captured any prior duplicates. This preserves correctness for strings like `"aab"` vs `"aba"` and `"aaa"` vs `"aaa"`.

### 2.3 Do not "double-consume" a duplicate
The OSA recurrence is **one-shot per cell**: once `dp[i][j]` is computed, that value is final. This prevents the same character from being used in two transpositions, which is exactly the OSA restriction and guarantees a deterministic, finite result even with heavy repetition.

---

## 3. Explicitly Handling Deterministic Ties

A **tie** occurs when two or more transitions produce the same minimum value at a cell. Examples:

- `dp[i-1][j] + 1 == dp[i][j-1] + 1` (insertion vs deletion tie)
- substitution cost equals transposition cost equals deletion cost
- match cost 0 ties with nothing else but must not be overridden

**Tie-breaking rule (deterministic, fixed order):**
When the `min(...)` is evaluated, Python's `min` returns the **first** argument achieving the minimum, and the arguments are always presented in this fixed order:

1. **Match / substitution** (`dp[i-1][j-1] + cost_sub`) — preferred when cost 0 (a true match).
2. **Deletion** (`dp[i-1][j] + 1`)
3. **Insertion** (`dp[i][j-1] + 1`)
4. **Transposition** (`dp[i-2][j-2] + 1`)

To make this explicit and audit-friendly, we restructure `min` into an ordered candidate list and pick the first minimum. This yields:

- **Match preferred over everything** (cost 0 wins outright).
- Among equal-cost non-match operations, **deletion > insertion > transposition** in tie order.
- Transposition is only chosen when it is *strictly* better than the alternatives.

This rule is **stable**: for fixed `a, b`, the computed distance is unique and reproducible. Note the distance value is unique regardless of tie order — tie-breaking only matters if one also returns an edit script (which we do not here), but we document it to make the algorithm fully specified.

---

## 4. Implementation (Standard Library Only)

```python
def damerau_levenshtein(a: str, b: str) -> int:
    """
    Edit distance with insertion, deletion, substitution, and adjacent
    transposition, each costing 1.

    Handles repeated values via explicit min over all transitions, and
    uses a fixed deterministic tie-breaking order:
        match/substitution  >  deletion  >  insertion  >  transposition
    (first minimum in that order wins).
    """
    n, m = len(a), len(b)

    # dp[i][j] = distance between a[:i] and b[:j]
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    # Base cases: only insertions or only deletions available.
    for i in range(n + 1):
        dp[i][0] = i
    for j in range(m + 1):
        dp[0][j] = j

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            cost_sub = 0 if a[i - 1] == b[j - 1] else 1

            # Ordered candidates — first minimum wins (deterministic ties).
            candidates = [
                (dp[i - 1][j - 1] + cost_sub, "match_or_sub"),  # 1st
                (dp[i - 1][j] + 1,           "delete"),         # 2nd
                (dp[i][j - 1] + 1,           "insert"),         # 3rd
            ]

            # Transposition candidate (only if applicable) — 4th.
            if (i > 1 and j > 1
                    and a[i - 1] == b[j - 2]
                    and a[i - 2] == b[j - 1]):
                candidates.append((dp[i - 2][j - 2] + 1, "transpose"))

            # Pick first minimum in fixed order.
            best = min(candidates, key=lambda c: c[0])[0]
            dp[i][j] = best

    return dp[n][m]
```

## 6. Summary of the Two Hard Cases

| Concern | How it is handled |
|---|---|
| **Repeated values** | DP takes the min over *all* transitions at every cell, so the optimal occurrence is always chosen. Transposition is checked against the two concrete adjacent positions, and the OSA one-shot rule prevents a character from being consumed twice. |
| **Deterministic ties** | Candidates are built in a fixed order (match/sub → delete → insert → transpose) and the **first** minimum is selected. This makes the result reproducible and, together with cost symmetry, keeps `d(a,b) = d(b,a)`. |

The distance value itself is unique regardless of tie order; the explicit ordering is documented so the algorithm is fully specified and any future edit-script reconstruction is stable.
