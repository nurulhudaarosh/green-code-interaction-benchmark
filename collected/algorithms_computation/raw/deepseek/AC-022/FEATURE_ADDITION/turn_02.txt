## Restated Original Problem

**Problem:** Compute the **Damerau–Levenshtein distance** (edit distance with adjacent transpositions) between two strings `s1` and `s2`.

**Allowed operations (each cost = 1):**
1. Insertion
2. Deletion
3. Substitution
4. Adjacent transposition (swap two neighboring characters)

**Original required output:**
- An integer — the minimum total edit cost to transform `s1` into `s2`.

**Original key constraints:**
- Deterministic output (no randomness).
- Standard library only (no external dependencies, no network access, no APIs, no human interaction).
- Must explicitly model the transposition transition in the DP recurrence.

**Original algorithm (DP with explicit transposition transition):**

Let `d[i][j]` = edit distance between `s1[:i]` and `s2[:j]`. Base cases `d[i][0] = i`, `d[0][j] = j`.

```
d[i][j] = min(
    d[i-1][j]   + 1,                      # deletion
    d[i][j-1]   + 1,                      # insertion
    d[i-1][j-1] + (s1[i-1] != s2[j-1]),   # match / substitution
    d[i-2][j-2] + 1                       # adjacent transposition (conditional)
)
```

Answer = `d[len(s1)][len(s2)]`. Complexity O(n·m) time, O(n·m) space.

---

## New Required Output (Feature Added)

In addition to the integer distance, the result must expose:

- **`operation_summary`** — a deterministic summary of the computation, defined here as the **number of major computational decisions/operations** made by the algorithm.

### Precise definition of `operation_summary`

A "major computational decision/operation" is counted as follows:

1. **Cell evaluations:** one per `(i, j)` cell evaluated in the DP table, i.e. `n · m` cells where `n = len(s1)`, `m = len(s2)`. Each cell evaluation involves deciding the minimum cost among the candidate moves.
2. **Transposition checks:** one per `(i, j)` cell where the transposition precondition is *tested* (i.e. `i > 1 and j > 1`), whether or not the swap actually applies. This counts the branch decision.

`operation_summary = cell_evaluations + transposition_checks`

This is fully deterministic, depends only on the input lengths, and reflects the actual decision points the algorithm traverses.

### Compatibility requirement

- When the feature is **disabled or not requested**, the function must behave exactly as before: it returns only the integer distance, with no change to any existing behavior, signature, or output.
- All original fields, constraints, and requirements remain unchanged.

## Python Implementation

```python
from typing import Union, Dict, Any


def damerau_levenshtein(
    s1: str,
    s2: str,
    return_summary: bool = False,
) -> Union[int, Dict[str, Any]]:
    """
    Compute the Damerau-Levenshtein distance between s1 and s2.

    Operations (each cost 1): insertion, deletion, substitution,
    and adjacent transposition.

    Parameters
    ----------
    s1, s2 : str
        Input strings.
    return_summary : bool, default False
        If False (default), returns an int (original behavior, unchanged).
        If True, returns a dict with 'distance' and 'operation_summary'.

    Returns
    -------
    int
        If return_summary is False.
    dict
        If return_summary is True: {'distance': int, 'operation_summary': int}.
    """
    n, m = len(s1), len(s2)

    # DP table: d[i][j] = edit distance between s1[:i] and s2[:j]
    d = [[0] * (m + 1) for _ in range(n + 1)]

    # Base cases
    for i in range(n + 1):
        d[i][0] = i
    for j in range(m + 1):
        d[0][j] = j

    # Counters for operation_summary
    cell_evaluations = 0
    transposition_checks = 0

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            # --- major computational decision #1: evaluate this cell ---
            cell_evaluations += 1

            cost_sub = 0 if s1[i - 1] == s2[j - 1] else 1

            d[i][j] = min(
                d[i - 1][j] + 1,             # deletion
                d[i][j - 1] + 1,             # insertion
                d[i - 1][j - 1] + cost_sub,  # match / substitution
            )

            # --- major computational decision #2: transposition precondition test ---
            if i > 1 and j > 1:
                transposition_checks += 1
                if (s1[i - 1] == s2[j - 2]
                        and s1[i - 2] == s2[j - 1]):
                    d[i][j] = min(d[i][j], d[i - 2][j - 2] + 1)

    distance = d[n][m]

    if not return_summary:
        return distance

    return {
        "distance": distance,
        "operation_summary": cell_evaluations + transposition_checks,
    }


if __name__ == "__main__":
    # Original behavior preserved (returns int)
    print(damerau_levenshtein("teh", "the"))            # 1
    print(damerau_levenshtein("kitten", "sitting"))     # 3
    print(damerau_levenshtein("", "abc"))               # 3

    # New feature enabled
    result = damerau_levenshtein("teh", "the", return_summary=True)
    print(result)
    # n=3, m=3 -> cells = 9
    # transposition checks: i>1 and j>1 -> (2,2),(2,3),(3,2),(3,3) = 4
    # operation_summary = 9 + 4 = 13
    # expected: {'distance': 1, 'operation_summary': 13}

    # Regression tests: original outputs must be unchanged
    tests = [
        ("", "", 0),
        ("", "abc", 3),
        ("abc", "", 3),
        ("abc", "abc", 0),
        ("abc", "abd", 1),
        ("abc", "ab", 1),
        ("ab", "abc", 1),
        ("ab", "ba", 1),
        ("ca", "abc", 3),
        ("kitten", "sitting", 3),
        ("teh", "the", 1),
        ("a cat", "an act", 3),
    ]

    ok = True
    for a, b, expected in tests:
        got = damerau_levenshtein(a, b)  # original call signature
        status = "OK " if got == expected else "FAIL"
        if got != expected:
            ok = False
        print(f"[{status}] d({a!r}, {b!r}) = {got}  (expected {expected})")

    print("\nAll original tests passed." if ok else "\nSome original tests failed.")

    # Summary feature tests

    assert r == {"distance": 1, "operation_summary": expected_summary}, r
    print("Summary feature OK:", r)
```

### Why `operation_summary` is deterministic and useful
- `cell_evaluations = n · m` — every DP cell where the four-way minimum is decided.
- `transposition_checks = max(n-1, 0) · max(m-1, 0)` — every cell where the swap precondition is explicitly tested.
- The value depends only on input lengths, giving a stable, reproducible measure of the work performed by the algorithm — no randomness, no environment dependence.

All original requirements (integer output, allowed operations, DP recurrence with explicit transposition, standard library only, determinism) remain fully intact when the feature is disabled.
