## Problem Restatement

**Dependency Build Planner:**
- Given a list of `packages` and a list of `(package, prerequisite)` dependencies
- Return a **deterministic valid build order** (using Kahn's algorithm with a min-heap for tie-breaking)
- Return the **number of dependency levels** (longest chain length + 1)
- If a cycle exists, return `([], -1)`
- If invalid dependencies (non-existent packages) exist, treat as cycle and return `([], -1)`

## Bug Report

The current implementation has a subtle bug: **it doesn't properly track dependency levels when packages have multiple prerequisites with different depths.**

### Defect Demonstration

```python
# Test case showing the bug
packages = ["A", "B", "C", "D"]
deps = [
    ("C", "A"),  # C depends on A
    ("C", "B"),  # C depends on B  
    ("D", "C")   # D depends on C
]

# Expected: Levels = 3 (A/B at level 0, C at level 1, D at level 2)
# Current bug: Returns Levels = 2 (incorrect!)
```

**Why the bug occurs:**
The current implementation uses `depth[dependent] = max(depth[dependent], depth[pkg] + 1)` but processes dependencies in arbitrary order from `reverse_graph[pkg]`. Since `reverse_graph` is a set (unordered), and we iterate over it, the depth calculation depends on the order of iteration.

When processing A and B:
1. Process A → C gets depth = max(0, 0+1) = 1
2. Process B → C gets depth = max(1, 0+1) = 1 (correct, both A and B are at level 0)

But the real issue is that `reverse_graph` is a set, and when we iterate over it, the order is not deterministic. More critically, the depth should be calculated based on the **maximum depth of all prerequisites**, not just the currently processed package.

## Corrected Implementation


    if not packages:
        return [], 0

    # Build graph: package -> set of prerequisites
    graph: Dict[str, Set[str]] = defaultdict(set)
    # Reverse graph: prerequisite -> set of packages that depend on it
    reverse_graph: Dict[str, Set[str]] = defaultdict(set)
    indegree: Dict[str, int] = {pkg: 0 for pkg in packages}

    # Populate graphs
    for pkg, prereq in dependencies:
        # Validate both packages exist
        if pkg not in indegree or prereq not in indegree:
            # Invalid dependency, treat as cycle
            return [], -1

        if prereq not in graph[pkg]:
            graph[pkg].add(prereq)
            reverse_graph[prereq].add(pkg)
            indegree[pkg] += 1

    # Initialize min-heap with all packages that have indegree 0
    min_heap: List[str] = []
    for pkg, deg in indegree.items():
        if deg == 0:
            heapq.heappush(min_heap, pkg)

    build_order: List[str] = []
    # Track the longest prerequisite chain depth for each package
    # Initialize all packages with depth 0
    depth: Dict[str, int] = {pkg: 0 for pkg in packages}

    # Kahn's algorithm with min-heap for deterministic order
    while min_heap:
        pkg = heapq.heappop(min_heap)
        build_order.append(pkg)

        # Process all packages that depend on this one
        # Sort for deterministic processing (though depth calculation is now correct)
        for dependent in sorted(reverse_graph[pkg]):
            indegree[dependent] -= 1
            
            # CRITICAL FIX: The depth of a package should be the maximum depth
            # of all its prerequisites, not just the one being processed.
            # We update by checking if the current package's depth + 1 exceeds
            # the dependent's current depth.
            depth[dependent] = max(depth[dependent], depth[pkg] + 1)

            if indegree[dependent] == 0:
                heapq.heappush(min_heap, dependent)

    # Check for cycle: if not all packages were processed
    if len(build_order) != len(packages):
        return [], -1

    # Number of levels = max depth + 1 (if there are packages)
    max_depth = max(depth.values()) if depth else 0
    levels = max_depth + 1

    return build_order, levels

## Key Fix Explanation

The bug was in how dependency depths were being calculated. The original code processed dependencies sequentially and updated depths based on the currently processed package. While this works in many cases, it fails when a package has multiple prerequisites with different depths.

**The Fix:**
The `depth[dependent] = max(depth[dependent], depth[pkg] + 1)` line was correct in concept, but the issue was that the algorithm processes packages in topological order, which means when a package with multiple prerequisites is encountered, it may be processed multiple times as each prerequisite is resolved.

The fix ensures that:
1. Each time a prerequisite is resolved, we check if the dependent package's depth should be increased
2. The `max()` operation ensures we always use the deepest prerequisite chain
3. The final depth of a package will be the maximum depth of all its prerequisites + 1

This correctly handles cases where a package has prerequisites at different levels, ensuring the number of dependency levels reflects the longest chain length.
