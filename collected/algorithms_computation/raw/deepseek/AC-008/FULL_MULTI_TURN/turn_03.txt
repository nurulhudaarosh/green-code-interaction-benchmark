## Problem Restatement: Mutable Range Sum Engine

**Original Problem:**
Maintain an integer array under two operations:
1. **Point replacement**: Replace the value at a specific index with a new value.
2. **Inclusive range-sum query**: Return the sum of elements from index `l` to `r` (inclusive).

**Input Format:**
- First line: integer `n` (array size)
- Second line: `n` integers (initial array values)
- Third line: integer `q` (number of operations)
- Next `q` lines: each operation is either:
  - `update idx new_val` — replace the value at index `idx` (1-indexed) with `new_val`
  - `query l r` — return the sum of elements from index `l` to `r` inclusive (1-indexed)

**Original Required Output:**
- For each `query` operation, output the result on a separate line in the exact order they appear.
- No other output should be produced.

**Existing Behavior:**
- Use a Fenwick tree for O(log n) updates and prefix sums.
- Process operations in order.
- Handle invalid indices deterministically (clamp to valid range or ignore).

---

## New Feature: `operation_summary` Field

**Feature Description:**
When requested, the system should return an additional `operation_summary` field containing a useful deterministic summary of the computation. For this task, the summary reports:
- **Total operations processed** (`total_operations`)
- **Number of update operations** (`updates_performed`)
- **Number of query operations** (`queries_performed`)
- **Total Fenwick tree steps** (sum of loop iterations across all updates and prefix sums) (`total_fenwick_steps`)
- **Number of successful updates** (within bounds) (`successful_updates`)
- **Number of valid queries** (l <= r after clamping) (`valid_queries`)

**Behavior:**
- All original fields and outputs remain unchanged when the feature is disabled.
- The feature is enabled by an optional command-line argument `--summary` or environment variable `ENABLE_SUMMARY=1`.
- When enabled, the summary is printed **after** all query results, as a JSON object on a single line.
- The summary is deterministic and independent of input order.

**Implementation:**
The Fenwick tree operations are instrumented to count loop iterations. Updates and queries are counted separately.

---

## Corrected Implementation with Feature

```python
import sys
import json
import os

class FenwickTree:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)
        self.step_count = 0  # track total loop iterations

    def build(self, arr):
        # O(n) build from array (1-indexed internally)
        for i, val in enumerate(arr, start=1):
            self.bit[i] += val
            j = i + (i & -i)
            if j <= self.n:
                self.bit[j] += self.bit[i]
            self.step_count += 1  # count build steps

    def update(self, idx, delta):
        # point update: add delta at position idx (1-indexed)
        steps = 0
        while idx <= self.n:
            self.bit[idx] += delta
            idx += idx & -idx
            steps += 1
            self.step_count += 1
        return steps

    def prefix_sum(self, idx):
        # sum of [1..idx] inclusive
        s = 0
        steps = 0
        while idx > 0:
            s += self.bit[idx]
            idx -= idx & -idx
            steps += 1
            self.step_count += 1
        return s, steps

    def range_sum(self, l, r):
        # inclusive range sum [l..r]
        if l > r:
            return 0, 0
        sum_r, steps_r = self.prefix_sum(r)
        sum_l, steps_l = self.prefix_sum(l - 1)
        return sum_r - sum_l, steps_r + steps_l

def main():
    # Check if summary feature is enabled
    enable_summary = False
    if len(sys.argv) > 1 and sys.argv[1] == '--summary':
        enable_summary = True
    elif os.environ.get('ENABLE_SUMMARY') == '1':
        enable_summary = True
    
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    
    it = iter(data)
    n = int(next(it))
    arr = [int(next(it)) for _ in range(n)]
    
    ft = FenwickTree(n)
    ft.build(arr)
    
    q = int(next(it))
    out_lines = []
    
    # Summary counters
    total_operations = 0
    updates_performed = 0
    queries_performed = 0
    successful_updates = 0
    valid_queries = 0
    total_fenwick_steps = ft.step_count  # include build steps
    
    for _ in range(q):
        op = next(it).decode().lower()
        total_operations += 1
        
        if op == 'update':
            idx = int(next(it))
            new_val = int(next(it))
            updates_performed += 1
            if 1 <= idx <= n:
                old_val = arr[idx - 1]
                delta = new_val - old_val
                arr[idx - 1] = new_val
                steps = ft.update(idx, delta)
                total_fenwick_steps += steps
                successful_updates += 1
            # else: silently ignore for deterministic behavior
            
        elif op == 'query':
            l = int(next(it))
            r = int(next(it))
            queries_performed += 1
            # Validate and clamp to valid range for deterministic behavior
            orig_l, orig_r = l, r
            if l < 1: l = 1
            if r > n: r = n
            if l <= r:
                result, steps = ft.range_sum(l, r)
                total_fenwick_steps += steps
                out_lines.append(str(result))
                valid_queries += 1
            else:
                out_lines.append("0")  # deterministic handling
                # No Fenwick steps for invalid query
        else:
            # Unknown operation: deterministic skip (no-op)
            pass
    
    # Output query results (original behavior)
    output = "\n".join(out_lines)
    
    # Add summary if enabled
    if enable_summary:
        summary = {
            "total_operations": total_operations,
            "updates_performed": updates_performed,
            "queries_performed": queries_performed,
            "successful_updates": successful_updates,
            "valid_queries": valid_queries,
            "total_fenwick_steps": total_fenwick_steps
        }
        if output:
            output += "\n" + json.dumps(summary)
        else:
            output = json.dumps(summary)
    
    sys.stdout.write(output)

if __name__ == "__main__":
    main()
```

**Key Features of This Implementation:**

1. **All original behavior preserved**: Query results are output in order on separate lines. The summary is only added when explicitly enabled.

2. **Deterministic summary**: Counts are computed deterministically based on the input, independent of execution order or environment.

3. **Feature enablement**: Can be enabled via `--summary` command-line flag or `ENABLE_SUMMARY=1` environment variable.

4. **Minimal overhead**: Counting steps adds O(1) work per operation and doesn't affect the algorithm's complexity.

5. **Backward compatible**: When the feature is disabled, the output is identical to the original implementation.

6. **Instrumentation**: The Fenwick tree tracks total loop iterations across all operations (build, updates, and prefix sums), providing a useful measure of computational effort.
