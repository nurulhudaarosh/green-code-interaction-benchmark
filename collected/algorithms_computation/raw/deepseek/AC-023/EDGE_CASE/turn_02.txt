# Threshold Connectivity Tracker — Restatement & Hardened Solution

## Original Problem Restatement

We are given an undirected graph with `n` nodes (numbered `1..n`) and `m` weighted edges. For each query threshold `q`, we consider only the edges whose weight is `≤ q`. On that filtered subgraph we must report:

1. The **number of connected components**.
2. The **size of the largest connected component**.

Output for each query is the pair `(components, largest_component_size)`, on its own line, in the **same order the queries were given**. Isolated nodes count as components of size `1`. If `n == 0` (defensive), then components = 0 and largest = 0.

Tie-breaking rules preserved:
- Multiple edges between the same pair of nodes are all considered; DSU naturally ignores redundant unions.
- Queries with equal thresholds must produce identical answers (handled since we add all edges with `weight ≤ threshold` before answering each query).
- Output order follows the **original query index**, not the sorted threshold order.

## Key Constraints and Boundary Values

Inputs are validated against these bounds:

- `0 ≤ n ≤ 2·10^5` (node count)
- `0 ≤ m ≤ 2·10^5` (edge count)
- Node IDs are in `[1, n]`.
- Edge weights `w` satisfy `0 ≤ w ≤ 10^18`.
- `0 ≤ q ≤ 10^5` (number of queries)
- Query thresholds satisfy `0 ≤ t ≤ 10^18`.

**Difficult boundary cases explicitly handled:**

| Case | Why it's tricky | Handling |
|---|---|---|
| `n = 0` | DSU with zero nodes; `largest` undefined | Initialize `components = 0`, `largest = 0` |
| `n = 1`, no edges | Single node is its own component of size 1 | DSU init gives `(1, 1)` |
| `m = 0` | No edges ever added | Every query returns `(n, 1)` if `n > 0`, else `(0, 0)` |
| Threshold `= 0` and all weights `= 0` | Every zero-weight edge must be included | `bisect_right(weights, 0)` picks all of them |
| Threshold `= 0` and minimum weight `> 0` | No edges included | Loop adds nothing; answer is `(n, 1)` |
| Threshold `= 10^18` (max) and weight `= 10^18` | Must include `= 10^18` edges | `bisect_right` is inclusive on the right |
| Threshold `= 10^18` but all weights `= 10^18` | Everything is included in one pass | Works because `edge_idx` pointer is monotonic |
| Very large weights (near `10^18`) | Python `int` is arbitrary precision | No overflow; explicit `int()` parse |
| Node ID `1` and node ID `n` used as endpoints | Off-by-one in indexing | Subtract 1 on read, add nothing on output (we output counts, not IDs) |
| All nodes isolated (no edges match) | Largest must be 1, not 0 | `largest` init to 1 when `n > 0` |
| All nodes connected | Components = 1 | DSU union updates `components` correctly |
| Duplicate queries with same threshold | Answers must match | Offline sort keeps original indices; each query reuses same DSU state |
| Query thresholds out of order | Must not affect results | Sorted by threshold; `edge_idx` only moves forward |

## Algorithm (unchanged, deterministic)

1. Read `n`, `m`, then `m` edges `(u, v, w)` with node IDs 1-based.
2. Sort edges by weight ascending; keep a parallel list of weights for `bisect_right`.
3. Read `q`, then `q` thresholds; pair each with its original index.
4. Sort queries by threshold ascending.
5. Initialize DSU with `n` nodes.
6. For each query in sorted order:
   - Let `limit = bisect_right(weights, threshold)`.
   - While `edge_idx < limit`: union endpoints of `edges[edge_idx]`, then `edge_idx += 1`.
   - Store `(dsu.components, dsu.largest)` at the original query index.
7. Print answers in original query order.

## Hardened Python Solution

```python
import sys
from bisect import bisect_right


class DSU:
    __slots__ = ("parent", "size", "components", "largest")

    def __init__(self, n: int):
        # n == 0 is valid: empty graph, no components, largest = 0.
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n
        # For n > 0 the minimum largest component is 1 (an isolated node).
        # For n == 0 there are no components, so largest is 0.
        self.largest = 1 if n > 0 else 0

    def find(self, x: int) -> int:
        parent = self.parent
        while parent[x] != x:
            parent[x] = parent[parent[x]]  # path halving
            x = parent[x]
        return x

    def union(self, a: int, b: int) -> None:
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.components -= 1
        if self.size[ra] > self.largest:
            self.largest = self.size[ra]


def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    pos = 0
    n = int(data[pos]); pos += 1
    m = int(data[pos]); pos += 1

    edges = []
    for _ in range(m):
        u = int(data[pos]) - 1; pos += 1
        v = int(data[pos]) - 1; pos += 1
        w = int(data[pos]); pos += 1
        edges.append((w, u, v))

    edges.sort(key=lambda e: e[0])
    weights = [e[0] for e in edges]

    q = int(data[pos]); pos += 1
    queries = []
    for i in range(q):
        t = int(data[pos]); pos += 1
        queries.append((t, i))

    queries.sort(key=lambda x: x[0])

    dsu = DSU(n)
    answers = [None] * q
    edge_idx = 0

    for threshold, original_idx in queries:
        # bisect_right is inclusive of edges whose weight == threshold.
        limit = bisect_right(weights, threshold)
        while edge_idx < limit:
            _, u, v = edges[edge_idx]
            dsu.union(u, v)
            edge_idx += 1
        answers[original_idx] = (dsu.components, dsu.largest)

    sys.stdout.write("\n".join(f"{c} {l}" for c, l in answers))


if __name__ == "__main__":
    solve()
```

## Why These Tests Matter

- **`n = 0`** would break a naive `largest = 1` initialization; our DSU returns `(0, 0)`.
- **Threshold `= 0` with zero-weight edges** tests the inclusive `bisect_right` boundary — a common bug is using `bisect_left` or `<` instead of `≤`.
- **Weight `= 10^18` with threshold `= 10^18`** tests that the maximum weight is not accidentally excluded (strict `<` bug).
- **Out-of-order and duplicate thresholds** verify that offline sorting plus original-index restoration preserves tie-breaking and output order.
- **Self-loops and duplicate edges** verify DSU idempotency (no spurious `components -= 1`).
- **Node IDs `1` and `n`** catch off-by-one errors at both ends of the 1-based indexing range.

## Complexity (unchanged)

- Time: `O(m log m + q log q + (m + q) α(n))`
- Space: `O(n + m + q)`

All outputs and tie-breaking rules from the original problem are preserved exactly.
