## Problem Restatement

**Capacity-Constrained 0/1 Knapsack**:
- Given `n` indivisible items, each with:
  - `weight[i]` (integer ≥ 0)
  - `value[i]` (integer ≥ 0)
- Given a knapsack `capacity` (integer ≥ 0)
- Select a subset of items to **maximize total value** subject to **total weight ≤ capacity**
- Return the **original indices** (0‑based) of selected items
- **Tie‑breaking**: If multiple subsets achieve the same maximum value, return the **lexicographically smallest** list of indices (i.e., compare the sorted lists element‑by‑element from smallest to largest index)

## Key Constraints (Handled)
- Weights and values can be zero or positive integers
- Capacity can be zero
- Number of items can be zero
- Ties involving zero‑weight, zero‑value items must respect lexicographic ordering

## Algorithm Description
1. **DP**: Use 1‑D array `dp[w]` = maximum value achievable with **exact** capacity `w`
   - Initialize `dp[0] = 0`, all others to `-inf`
   - For each item `i` (in original order), update `dp` from high to low capacity
2. **Optimal value**: Find `best_val = max(dp[0..capacity])`
3. **Reconstruction** (lexicographically smallest):
   - Find the smallest capacity `best_cap` that achieves `best_val`
   - Iterate items from `i = 0` to `n-1`:
     - If `weights[i] ≤ best_cap` AND `dp[best_cap] == dp[best_cap - weights[i]] + values[i]`, then include item `i` (this greedy forward pass ensures smallest indices are preferred)
   - Return the selected indices

## Implementation with Edge Cases

```python
def solve_knapsack(weights, values, capacity):
    """
    Returns the list of original indices (0-based) of items selected
    to maximize total value under capacity.
    Ties are broken by lexicographically smallest index list.
    
    Handles:
    - Zero capacity
    - Zero-weight items
    - Zero-value items
    - Empty item list
    - All items too heavy
    - Large capacities/weights (within memory limits)
    """
    n = len(weights)
    if n == 0:
        return []
    
    # DP: dp[w] = max value with exact weight w
    NEG_INF = -10**18
    dp = [NEG_INF] * (capacity + 1)
    dp[0] = 0
    
    # Process items in original order (important for tie-breaking)
    for i in range(n):
        w = weights[i]
        v = values[i]
        # Skip items with weight > capacity (can't be used)
        if w > capacity:
            continue
        # Descending update to prevent reuse
        for cap in range(capacity, w - 1, -1):
            if dp[cap - w] != NEG_INF:
                new_val = dp[cap - w] + v
                if new_val > dp[cap]:
                    dp[cap] = new_val
    
    # Find the best value and the smallest capacity achieving it
    best_val = max(dp)
    best_cap = 0
    for cap in range(capacity + 1):
        if dp[cap] == best_val:
            best_cap = cap
            break
    
    # Reconstruct lexicographically smallest optimal subset
    selected = []
    rem_cap = best_cap
    
    for i in range(n):
        w = weights[i]
        v = values[i]
        # Check if item i can be included in some optimal solution
        if w <= rem_cap and dp[rem_cap] == dp[rem_cap - w] + v:
            selected.append(i)
            rem_cap -= w
    
    return selected
```

## Key Points About the Implementation

1. **Lexicographic Tie‑Breaking**: The forward reconstruction pass (iterating `i` from 0 to n‑1) naturally produces the lexicographically smallest list because we greedily include each smaller index if it can still lead to an optimal solution.

2. **Zero‑Weight Items**: These are handled correctly. Since they don't consume capacity, they'll be included if they add positive value (or if they're needed for tie‑breaking).

3. **Zero‑Value Items**: These won't affect the optimal value but might be included in the reconstruction if they appear early and don't hurt optimality. The algorithm may include them because `dp[rem_cap] == dp[rem_cap - w] + v` holds when `v=0`. This correctly produces the lexicographically smallest list when values are tied.

4. **Boundary Values**: The algorithm handles:
   - `capacity = 0`
   - `weights[i] = 0`
   - `values[i] = 0`
   - `n = 0`
   - Items with `weight > capacity` (skipped in DP, but checked during reconstruction)
   - Very large `capacity` (memory permitting)

5. **Efficiency**: O(n × capacity) time, O(capacity) space.
