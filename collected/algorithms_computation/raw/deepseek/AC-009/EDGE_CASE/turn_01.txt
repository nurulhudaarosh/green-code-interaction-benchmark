I’ll implement a deterministic solution for the unbounded coin change problem that returns the minimum number of coins and the actual combination.

```python
def coin_change(coins, target):
    """
    Returns (min_coins, combination) for unbounded coin change.
    If impossible: returns (-1, [])
    """
    if target < 0:
        return -1, []
    if target == 0:
        return 0, []

    # DP array: minimum coins to make amount i
    dp = [float('inf')] * (target + 1)
    dp[0] = 0

    # Keep track of which coin was used to make amount i
    # We'll store one coin denomination that leads to the optimal solution
    used_coin = [-1] * (target + 1)

    # Unbounded coin change: iterate amounts then coins
    for amount in range(1, target + 1):
        for coin in coins:
            if amount >= coin and dp[amount - coin] + 1 < dp[amount]:
                dp[amount] = dp[amount - coin] + 1
                used_coin[amount] = coin

    if dp[target] == float('inf'):
        return -1, []

    # Reconstruct the combination
    combination = []
    remaining = target
    while remaining > 0:
        coin = used_coin[remaining]
        combination.append(coin)
        remaining -= coin

    # The reconstruction gives coins in reverse order; we can reverse for clarity
    combination.reverse()

    return dp[target], combination

```

**Key constraints & required output:**

- **Constraints:**
  - `coins` is a list of positive integers (denominations).
  - `target` is a non-negative integer.
  - Coins can be reused unlimited times.
  - If no combination sums to `target`, return `-1` and an empty list.

- **Required output:**
  - A tuple `(min_coins, combination)` where:
    - `min_coins` is the minimum number of coins needed (or `-1` if impossible).
    - `combination` is a list of coin values that sum to `target`, using exactly `min_coins` coins (or empty list if impossible).

**Algorithm description:**

- Use **1D unbounded coin-change DP**:
  - `dp[amount]` = minimum coins to make `amount`.
  - Initialize `dp[0] = 0`, others to infinity.
  - Iterate `amount` from 1 to `target`, and for each coin, update `dp[amount] = min(dp[amount], dp[amount-coin] + 1)` if `coin <= amount`.
- **Deterministic reconstruction**:
  - Maintain `used_coin[amount]` storing one coin that gave the optimal value for that amount.
  - After DP, if `dp[target]` is finite, backtrack using `used_coin` to build the combination.
- The algorithm is deterministic because:
  - We iterate coins in the given order.
  - For equal `dp[amount-coin] + 1`, we only update if strictly smaller (so the first coin that achieves the minimum is chosen, making reconstruction stable).
- Time complexity: O(target * len(coins)), space: O(target).
