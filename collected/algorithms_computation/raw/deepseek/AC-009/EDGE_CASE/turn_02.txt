## Problem Restatement

**Minimum Coin Construction (Unbounded Coin Change)**

Given:
- A list of coin denominations `coins` (positive integers)
- A target amount `target` (non-negative integer)

Find:
- The **minimum number of coins** needed to sum to `target`
- The **actual combination** of coins that achieves this minimum

Rules:
- Coins may be reused unlimited times (unbounded)
- If it's impossible to form `target`, return `(-1, [])`
- The solution must be **deterministic** (same input always gives same output)
- Tie-breaking: When multiple combinations achieve the same minimum coin count, choose the one that uses coins in the order they first appear in the `coins` list during DP reconstruction

## Enhanced Implementation with Edge Case Handling

```python
def coin_change(coins, target):
    """
    Returns (min_coins, combination) for unbounded coin change.
    If impossible: returns (-1, [])
    
    Deterministic tie-breaking: prefers coins that appear earlier in the coins list
    when multiple combinations have the same minimum count.
    """
    # --- Edge case: target is negative (not permitted by problem statement, but safe) ---
    if target < 0:
        return -1, []
    
    # --- Edge case: empty coin list ---
    if not coins:
        return -1, [] if target > 0 else (0, [])
    
    # --- Edge case: target is zero (smallest permitted input) ---
    if target == 0:
        return 0, []
    
    # --- Filter out coins that are larger than target (can never be used) ---
    # This is optional but improves efficiency and handles disconnected structures
    filtered_coins = [c for c in coins if c <= target]
    if not filtered_coins:
        return -1, []
    
    # --- DP initialization ---
    # dp[amount] = minimum coins to make amount
    dp = [float('inf')] * (target + 1)
    dp[0] = 0
    
    # used_coin[amount] = the coin denomination used to achieve dp[amount]
    used_coin = [-1] * (target + 1)
    
    # --- Unbounded DP: amount outer loop, coins inner loop ---
    # This ordering ensures we can reuse coins and gives deterministic reconstruction
    for amount in range(1, target + 1):
        for coin in filtered_coins:  # Iterate in original order for determinism
            if amount >= coin:
                candidate = dp[amount - coin] + 1
                # Strictly less ensures deterministic tie-breaking:
                # first coin that achieves the minimum is chosen
                if candidate < dp[amount]:
                    dp[amount] = candidate
                    used_coin[amount] = coin
    
    # --- Check if target is reachable ---
    if dp[target] == float('inf'):
        return -1, []
    
    # --- Reconstruction (deterministic) ---
    combination = []
    remaining = target
    while remaining > 0:
        coin = used_coin[remaining]
        if coin == -1:  # Safety check, should not happen if dp is finite
            return -1, []
        combination.append(coin)
        remaining -= coin
    
    # Reverse because we built from target down to 0
    combination.reverse()
    
    return dp[target], combination
```

## Key Edge Cases Handled

1. **Smallest permitted input**: `target = 0` returns `(0, [])` regardless of coins
2. **Empty coin list**: Returns `(-1, [])` for `target > 0`, `(0, [])` for `target = 0`
3. **Coins larger than target**: Filtered out (they can never contribute to a sum ≤ target)
4. **All coins larger than target**: Returns `(-1, [])`
5. **Impossible combinations**: Returns `(-1, [])`
6. **Tie-breaking**: Uses strict `<` in DP update, so the first coin that achieves the minimum is always chosen (deterministic)
