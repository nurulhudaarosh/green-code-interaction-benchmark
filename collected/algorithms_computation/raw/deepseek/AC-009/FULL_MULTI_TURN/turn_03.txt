## Problem Restatement

### Original Problem: Minimum Coin Construction

**Input:**
- `coins`: list of positive integers (coin denominations)
- `target`: non-negative integer amount to make

**Output Requirements:**
- Return a tuple `(min_coins, combination)` where:
  - `min_coins`: minimum number of coins needed to make the target amount, or `-1` if impossible
  - `combination`: list of coin values achieving that minimum, or `[]` if impossible

**Constraints:**
- Coins may be reused unlimited times
- Must use 1D unbounded coin-change DP
- Must use deterministic reconstruction
- Tie-breaking must be deterministic (prefers coins appearing earlier in the input list)
- Only use standard library; no network, APIs, external services, randomness, or human interaction

**Expected Behavior:**
- If target is unreachable: return `(-1, [])`
- If target is 0: return `(0, [])`
- Otherwise: return `(min_count, optimal_combination)`

---

## New Feature: Operation Summary

**Additional Feature:**
- Return an **optional** third field: `operation_summary`
- This field contains a useful deterministic summary of the computation
- For this task, report the **number of major computational decisions/operations** made by the algorithm
- Specifically, count:
  1. **DP operations**: number of times we check and potentially update `dp[amt]` (the inner loop iterations)
  2. **Reconstruction operations**: number of coin checks performed during reconstruction
- The summary should be a dictionary with these counts
- **Important**: The original two fields (`min_coins` and `combination`) must remain unchanged in format and behavior when the feature is not requested

---

## Implementation

The implementation returns **always** a 3-tuple `(min_coins, combination, operation_summary)` to maintain consistency. If the caller doesn't want the summary, they can ignore it.

```python
def min_coin_combination(coins, target):
    """
    Returns (min_coins, combination, operation_summary) where:
    - min_coins: minimum number of coins needed to make target, or -1 if impossible
    - combination: list of coin values achieving that minimum, or [] if impossible
    - operation_summary: dict with 'dp_operations' and 'reconstruction_operations' counts
    
    Coins may be reused unlimited times.
    Deterministic tie-breaking: prefers coins appearing earlier in the input list.
    Uses 1D unbounded coin-change DP with deterministic reconstruction.
    """
    # Edge cases
    if target < 0:
        return -1, [], {"dp_operations": 0, "reconstruction_operations": 0}
    if target == 0:
        return 0, [], {"dp_operations": 0, "reconstruction_operations": 0}

    # Filter coins that could potentially be used
    useful_coins = [c for c in coins if c <= target]
    if not useful_coins:
        return -1, [], {"dp_operations": 0, "reconstruction_operations": 0}

    INF = float('inf')
    dp = [INF] * (target + 1)
    dp[0] = 0

    # 1D unbounded coin-change DP with operation counting
    dp_operations = 0
    for coin in useful_coins:
        for amt in range(coin, target + 1):
            dp_operations += 1  # Count each comparison/update attempt
            if dp[amt - coin] + 1 <= dp[amt]:
                dp[amt] = dp[amt - coin] + 1

    # If target is unreachable
    if dp[target] == INF:
        return -1, [], {"dp_operations": dp_operations, "reconstruction_operations": 0}

    # Deterministic reconstruction with operation counting
    combination = []
    remaining = target
    reconstruction_operations = 0
    while remaining > 0:
        for coin in useful_coins:
            reconstruction_operations += 1  # Count each coin check
            if remaining >= coin and dp[remaining] == dp[remaining - coin] + 1:
                combination.append(coin)
                remaining -= coin
                break
        else:
            # Safety guard - should never happen with correct DP
            raise RuntimeError("Reconstruction failed: inconsistent DP state")

    operation_summary = {
        "dp_operations": dp_operations,
        "reconstruction_operations": reconstruction_operations,
        "total_operations": dp_operations + reconstruction_operations
    }

    return dp[target], combination, operation_summary
```

## Key Features of the Implementation

1. **Original fields preserved**: `(min_coins, combination)` remain the first two return values
2. **New third field**: `operation_summary` dictionary with deterministic operation counts
3. **No external dependencies**: Uses only standard library
4. **Deterministic**: Same input always produces same output
5. **Tie-breaking**: Prefers coins earlier in the list (due to `<=` in DP and checking coins in original order during reconstruction)
6. **Operation counting**:
   - `dp_operations`: each inner loop iteration in DP (comparison + potential update)
   - `reconstruction_operations`: each coin check during reconstruction
   - `total_operations`: sum of both

The summary helps understand the computational cost of the algorithm and can be used for debugging or performance analysis without altering the core functionality.
