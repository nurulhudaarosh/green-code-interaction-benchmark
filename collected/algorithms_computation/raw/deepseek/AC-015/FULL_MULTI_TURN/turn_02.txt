# Maximum Flow Planner — Bug Report & Fix

## Problem Restatement

**Task:** Given a directed capacitated network (list of edges `(u, v, cap)` in a fixed order), a source `s`, and a sink `t`, compute:

1. The **maximum s-t flow value**.
2. The **flow on each original edge**, returned in the *same order* as the input edge list.

**Required behavior:**

- Use **Dinic's blocking-flow algorithm** (BFS level graph + DFS blocking flow with current-arc optimization).
- Enforce the capacity constraint `0 ≤ f(e) ≤ cap(e)` and flow conservation at all nodes except `s` and `t`.
- Be **deterministic** — same input ⇒ same output, no randomness.
- **Preserve original edge order** in the output array: `flows[i]` must correspond to `edges[i]`.
- **Deterministic tie handling**: when multiple blocking-flow augmentations are possible, always pick edges in the *same deterministic order* (e.g., insertion order of adjacency lists), and always consume the smallest-index eligible edge first.

**Expected output:** `(max_flow_value, [flow_for_edge_0, flow_for_edge_1, ...])` with `len(flows) == len(edges)`.

## Bug Report — What the Current Implementation Gets Wrong

The typical buggy implementation has these defects:

1. **Adjacency list order is not preserved.** When building the residual graph, edges are appended per-node, but the *original-edge index* is not tracked. Reverse arcs are identified by `eid ^ 1`, and the flow on original edge `i` is recovered as `cap[2*i + 1]`. This works **only if forward and reverse arcs are inserted adjacently in pairs**. If the code appends all forward arcs first and then all reverse arcs (a common shortcut), `eid ^ 1` no longer points to the paired arc, and the recovered flow is attached to the **wrong original edge**.

2. **Non-deterministic tie handling in the blocking DFS.** Some variants iterate over the adjacency list of a node using a `set` or use dictionary iteration, which in some Python versions can produce different orders across runs (or at least makes the chosen path unspecified). The result is a *valid* max flow, but not the *required* one, and it breaks the "deterministic tie handling" rule.

3. **Off-by-one in flow recovery for self-loops or parallel edges.** If an original edge is a self-loop `(u, u, c)`, the naive pairing `2*i / 2*i+1` still works, but flow recovery via `cap[2*i+1]` fails if the forward arc's residual was never decremented (a self-loop can never carry flow in a shortest-path level graph, but the *reported* value must still be `0`, not garbage from an unrelated pair).

4. **Output length mismatch.** If the residual graph is built only from edges with `cap > 0`, zero-capacity original edges are dropped, so `len(flows) < len(edges)` and the order is broken.

## Demonstration of the Defect

Consider this small valid input:

```
n = 4, s = 0, t = 3
edges = [
  (0, 1, 5),   # index 0
  (0, 2, 5),   # index 1
  (1, 3, 5),   # index 2
  (2, 3, 5),   # index 3
]
```

Max flow = 10. A deterministic Dinic run that scans adjacency lists in insertion order picks the path `0→1→3` first (5 units), then `0→2→3` (5 units). Correct flows: `[5, 5, 5, 5]`.

**Buggy build order** — suppose the code builds the residual graph by appending *all* forward arcs first, then *all* reverse arcs:

```
to  = [1, 2, 3, 3,  0, 0, 1, 2]
cap = [5, 5, 5, 5,  0, 0, 0, 0]
```

Now `eid ^ 1` pairs: `0↔1`, `2↔3`, `4↔5`, `6↔7`. But forward arc for edge `0` is `eid=0`, whose partner is `eid=1` — which is the forward arc for edge `1`, **not** a reverse arc. Recovering `flows[0] = cap[0 ^ 1] = cap[1] = 5` (the untouched forward capacity of edge 1) is coincidentally right here, but after augmentation `flows[0]` becomes `cap[1]` which reflects edge 1's residual, not edge 0's reverse. On asymmetric examples the reported flows are simply wrong. Even worse, the reverse arc of edge 0 is at `eid = 4`, so the actual flow on edge 0 lives at `cap[4]`, which is never read.

**Result:** the returned `flows` array does not correspond to `edges` in order, violating the "preserve original edge order" rule.

## Corrected Implementation

The fix: **always insert the forward arc and its reverse arc as an adjacent pair**, record `orig_id` per arc, and recover each original edge's flow from its **reverse arc's residual capacity**, located at `2*i + 1`. Adjacency lists are built by appending in insertion order, so DFS tie-breaking is deterministic. Do not drop zero-capacity edges — they must still appear in the output.

```python
import sys
from collections import deque

def max_flow(n, edges, s, t):
    """
    n     : number of nodes (0 .. n-1)
    edges : list of (u, v, cap) in ORIGINAL order
    s, t  : source and sink
    returns: (max_flow_value, flows_per_original_edge)
    Deterministic: adjacency lists are in insertion order; DFS consumes
    the smallest-index eligible residual arc first.
    """
    m = len(edges)

    # ---- Residual graph: forward/reverse arcs inserted ADJACENTLY ----
    # For original edge i: forward arc index = 2*i, reverse = 2*i + 1.
    to      = [0] * (2 * m)
    cap     = [0] * (2 * m)
    graph   = [[] for _ in range(n)]

    for i, (u, v, c) in enumerate(edges):
        fwd = 2 * i
        rev = 2 * i + 1
        to[fwd], cap[fwd] = v, c
        to[rev], cap[rev] = u, 0
        graph[u].append(fwd)   # insertion order preserved
        graph[v].append(rev)   # insertion order preserved

    # ---- Dinic's algorithm -------------------------------------------
    flow_value = 0
    level = [-1] * n
    it    = [0]  * n

    def bfs():
        for i in range(n):
            level[i] = -1
        level[s] = 0
        q = deque([s])
        while q:
            u = q.popleft()
            for eid in graph[u]:
                v = to[eid]
                if cap[eid] > 0 and level[v] < 0:
                    level[v] = level[u] + 1
                    q.append(v)
        return level[t] >= 0

    sys.setrecursionlimit(1_000_000)

    def dfs(u, pushed):
        if u == t:
            return pushed
        while it[u] < len(graph[u]):
            eid = graph[u][it[u]]          # deterministic: lowest index first
            v = to[eid]
            if cap[eid] > 0 and level[v] == level[u] + 1:
                d = dfs(v, min(pushed, cap[eid]))
                if d > 0:
                    cap[eid]     -= d
                    cap[eid ^ 1] += d      # paired adjacent arcs
                    return d
            it[u] += 1
        return 0

    INF = float('inf')
    while bfs():
        for i in range(n):
            it[i] = 0
        while True:
            pushed = dfs(s, INF)
            if pushed == 0:
                break
            flow_value += pushed

    # ---- Flow recovery: flow on original edge i = residual on its reverse
    #      arc (index 2*i + 1). Correct because forward/reverse are paired.
    flows = [cap[2 * i + 1] for i in range(m)]
    return flow_value, flows


# ----------------------------- Self-test ------------------------------
if __name__ == "__main__":
    # Defect demo network
    edges = [(0, 1, 5), (0, 2, 5), (1, 3, 5), (2, 3, 5)]
    val, flows = max_flow(4, edges, 0, 3)
    assert val == 10, val
    assert flows == [5, 5, 5, 5], flows
    print("Demo 1:", val, flows)

    # Zero-capacity edge must still be reported
    edges = [(0, 1, 0), (0, 2, 3), (2, 1, 3), (1, 3, 3)]
    val, flows = max_flow(4, edges, 0, 3)
    assert flows[0] == 0 and len(flows) == len(edges)
    print("Demo 2:", val, flows)

    # Parallel edges: each must carry its own reported flow
    edges = [(0, 1, 2), (0, 1, 3), (1, 2, 5)]
    val, flows = max_flow(3, edges, 0, 2)
    assert val == 5
    assert sum(flows[:2]) == 5 and flows[2] == 5
    print("Demo 3:", val, flows)

    # Self-loop must report 0 and not corrupt other indices
    edges = [(0, 0, 7), (0, 1, 4), (1, 2, 4)]
    val, flows = max_flow(3, edges, 0, 2)
    assert val == 4 and flows == [0, 4, 4], flows
    print("Demo 4:", val, flows)
```

**Output:**

```
Demo 1: 10 [5, 5, 5, 5]
Demo 2: 3 [0, 3, 3, 3]
Demo 3: 5 [2, 3, 5]
Demo 4: 4 [0, 4, 4]
```

## Why the Fix Works

- **Adjacent pairing (`2*i`, `2*i+1`)** makes `eid ^ 1` always the correct partner, so `cap[2*i+1]` is exactly the flow pushed along original edge `i`.
- **Insertion-order adjacency lists** plus the `it[u]` current-arc pointer yield a **deterministic** blocking flow: for each node, the lowest-index eligible residual arc is always tried first.
- **Zero-capacity and self-loop edges are kept** in the graph and in the output, so `len(flows) == len(edges)` and the order is exact.
- **No unrelated requirements changed**: still Dinic's algorithm, still BFS level graph + DFS blocking flow, still standard library only, still deterministic, still original-order output.
