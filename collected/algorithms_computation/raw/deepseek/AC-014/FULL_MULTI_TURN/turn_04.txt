## Original Problem Restatement: One-Dimensional K-Cluster Partition

**Given:** A list of `n` one-dimensional points and an integer `k` with `1 ≤ k ≤ n`.

**Task:**
1. **Sort** the points.
2. **Partition** the sorted points into exactly `k` contiguous, non-empty clusters.
3. **Minimize** the sum of squared deviations from each cluster's mean (within-cluster sum of squares, WCSS). For a cluster spanning sorted indices `x[l..r]`:

```
cost(l, r) = Σ_{i=l..r} (x[i] − mean(l,r))²
           = Σ x[i]² − (Σ x[i])² / (r − l + 1)
```

**Required outputs (unchanged):**
- `min_cost` (float): minimum total WCSS.
- `boundaries` (list[int]): the `k` 0-based start indices of each cluster in sorted order.

**Required behaviors (unchanged):**
- Use **prefix sums** of `x` and `x²` for O(1) interval cost.
- Use **interval-cost dynamic programming**: `dp[j][i] = min over t of dp[j−1][t] + cost(t, i−1)`.
- **Deterministic tie handling**: among all optimal partitions, return the one whose boundary list is **lexicographically smallest** (realized by choosing the largest optimal split index `t` at each DP cell via `<=` with ascending `t`).
- Constraint: raise `ValueError` if `k < 1` or `k > n`.
- Standard library only; no randomness, network, or external services.
- Complexity O(k·n²) time, O(k·n) space.

---

## Explicit Handling of Difficult Valid Cases

### Case A — Repeated Values

Repeated values are valid inputs and require care because:

1. **Prefix sums are still exact** when using `x[i]²` — no division-by-zero or negative counts occur since `cnt = r − l + 1 ≥ 1`.
2. **WCSS can be exactly 0** for any cluster whose members are all equal. This produces many cost ties between partitions (e.g., splitting a run of equal values at different points costs the same).
3. **Floating-point equality is exact here** for integer inputs: `sq − s²/cnt` with `sq = cnt·v²` and `s = cnt·v` gives `cnt·v² − (cnt·v)²/cnt = cnt·v² − cnt·v² = 0` exactly in IEEE-754 for integer `v` and modest `cnt`. Still, we use a small tolerance in tests to be robust.

**Handling rule:** When ties occur among equal-cost partitions, the **lexicographically-smallest boundary list** rule decides. With repeated values this typically means **keeping equal values together** when `k` allows, because merging a run into one cluster costs 0, and the lex-smallest boundaries prefer earlier (smaller) split indices... but the largest-`t` rule at each cell can push splits right. We must verify with concrete examples rather than assume.

### Case B — Deterministic Ties

A **tie** is two distinct feasible partitions with **equal total cost**. The rule is: return the partition whose boundary list `[b_0, b_1, …, b_{k−1}]` is lexicographically smallest.

**Why `<=` with ascending `t` gives this:**
- The DP's last decision is the split index `t = b_{k−1}` for the final cluster.
- Two candidates with identical cost sharing the same `[b_0, …, b_{k−2}]` differ only in `b_{k−1}`. Lexicographic comparison of equal-length lists compares leftmost differences first, but here all earlier entries are equal, so the comparison reduces to `b_{k−1}`. The **smaller** `b_{k−1}` wins — which means **smaller** `t`... wait, we must be careful.

Let me reason carefully. Boundaries are `[b_0, b_1, …, b_{k−1}]` with `b_0 = 0 < b_1 < … < b_{k−1} < n`. Lexicographic order compares `b_0` first (always 0, equal), then `b_1`, then `b_2`, etc. The **last** element `b_{k−1}` is only consulted if all earlier boundaries are equal.

At DP cell `(j, i)`, the recurrence picks `t = b_{j−1}` for the last cluster `[t, i−1]`. Two candidates with equal cost **and the same predecessor state** `dp[j−1][t]` and hence the same `[b_0, …, b_{j−2}]` differ only at `b_{j−1} = t`. Lexicographically, **smaller `b_{j−1}` wins** (since it's the first position where they differ, and smaller is lex-smaller).

So the correct rule to enforce lex-smallest boundaries is: **among equal-cost `t`, choose the SMALLEST `t`.** That means using strict `<` with **ascending** `t` (keeps the first/smallest), not `<=`.

> **Important correction to prior reasoning:** My earlier implementation used `<=` with ascending `t`, which keeps the **largest** optimal `t`. That yields the **lexicographically largest** boundary list, not the smallest. For `x = [0, 2, 4], k = 2`: costs at `t=1` and `t=2` are both 2.0.  
> - `t=1` → boundaries `[0, 1]`  
> - `t=2` → boundaries `[0, 2]`  
> Lex-smallest is `[0, 1]`, which comes from the **smaller** `t`. So `<` with ascending `t` (smallest `t`) is correct; `<=` was wrong.

To make this **explicit and order-independent**, we implement the tie-break by directly comparing candidate boundary lists when costs tie, rather than relying on loop order. This is unambiguous, verifiable, and robust.

### Correct, Explicit Tie-Break

At DP cell `(j, i)`, each candidate `t` produces a full boundary list:
`boundaries(dp[j−1][t]) + [t]`.

When two candidates have equal cost, compare their boundary lists lexicographically and keep the smaller. To do this efficiently without materializing full lists everywhere, note that `boundaries(dp[j−1][t])` is itself lex-smallest for that subproblem; so the comparison between candidate `t1 < t2` reduces to: is `boundaries_t1 + [t1]` < `boundaries_t2 + [t2]`? Since `t1 < t2`, the first position where they can differ is somewhere in the predecessor boundaries; if predecessors are identical, `t1 < t2` decides in favor of `t1`.

We therefore store, alongside `dp` and `split`, the **lex-smallest boundary list** for each `(j, i)` — feasible here since `k·n` is small. This makes the tie-break explicit and testable.

## Implementation (explicit deterministic tie-break)

```python
def partition_points(points, k):
    """
    Sort 1D points, partition into exactly k contiguous non-empty clusters
    minimizing within-cluster sum of squares (WCSS).

    Returns:
        (min_cost, boundaries)

    boundaries: list of k 0-based start indices of clusters in sorted order,
    chosen to be LEXICOGRAPHICALLY SMALLEST among all optimal partitions.

    Tie-break is explicit: at each DP cell, among equal-cost candidates we
    compare the full boundary lists and keep the lexicographically smallest.
    This makes the result independent of loop direction or comparator style.
    """
    n = len(points)
    if k < 1 or k > n:
        raise ValueError("k must satisfy 1 <= k <= n")

    x = sorted(points)

    P = [0.0] * (n + 1)   # sum of x[0..i-1]
    Q = [0.0] * (n + 1)   # sum of x[0..i-1]^2
    for i in range(n):
        P[i + 1] = P[i] + x[i]
        Q[i + 1] = Q[i] + x[i] * x[i]

    def cost(l, r):
        """Inclusive WCSS of x[l..r]."""
        cnt = r - l + 1
        s = P[r + 1] - P[l]
        sq = Q[r + 1] - Q[l]
        return sq - (s * s) / cnt

    INF = float("inf")
    dp = [[INF] * (n + 1) for _ in range(k + 1)]
    # best_bounds[j][i] = lex-smallest boundary list for dp[j][i]
    best_bounds = [[None] * (n + 1) for _ in range(k + 1)]
    dp[0][0] = 0.0
    best_bounds[0][0] = []

    for j in range(1, k + 1):
        for i in range(j, n + 1):
            best = INF
            best_b = None
            for t in range(j - 1, i):
                if dp[j - 1][t] == INF:
                    continue
                c = dp[j - 1][t] + cost(t, i - 1)
                cand_b = best_bounds[j - 1][t] + [t]
                if c < best - 1e-12:
                    best = c
                    best_b = cand_b
                elif abs(c - best) <= 1e-12:
                    # Explicit lexicographic tie-break
                    if best_b is None or cand_b < best_b:
                        best = c
                        best_b = cand_b
            dp[j][i] = best
            best_bounds[j][i] = best_b

    return dp[k][n], best_bounds[k][n]


# ---------------- deterministic self-tests ----------------
if __name__ == "__main__":
    # --- Original behavior preserved ---
    c, b = partition_points([1, 2, 3, 10, 11, 12], 2)
    assert abs(c - 2.0) < 1e-9 and b == [0, 3], (c, b)

    c, b = partition_points([5, 1, 3, 2, 4], 5)
    assert c == 0.0 and b == [0, 1, 2, 3, 4], (c, b)

    c, b = partition_points([1, 2, 3], 1)
    assert abs(c - 2.0 / 3.0) < 1e-9 and b == [0], (c, b)

    # --- Explicit tie case: x=[0,2,4], k=2, both t=1 and t=2 give cost 2.0 ---
    # Lex-smallest boundaries: [0,1] (t=1) beats [0,2] (t=2).
    c, b = partition_points([0, 2, 4], 2)
    assert abs(c - 2.0) < 1e-9, c
    assert b == [0, 1], b

    # Another tie: x=[0,0,10,10], k=3
    # Partitions (all cost 0): [0],[0],[10,10] -> [0,1,2]
    #                          [0],[0,10],[10] -> [0,1,3]  (cost >0 actually)
    # Verify the true optimum and lex-smallest boundaries.
    c, b = partition_points([0, 0, 10, 10], 3)
    # Best cost 0 requires each cluster constant: only [0],[0],[10,10]
    # or [0,0],[10],[10]. Lex-smallest boundaries: [0,1,2].
    assert abs(c - 0.0) < 1e-9, c
    assert b == [0, 1, 2], b

    # --- Repeated values ---
    # All equal -> any split costs 0; lex-smallest boundaries are 0..k-1.
    c, b = partition_points([7, 7, 7, 7, 7], 3)
    assert abs(c - 0.0) < 1e-9, c
    assert b == [0, 1, 2], b

    # Repeated values with two groups
    c, b = partition_points([0.0, 0.0, 0.0, 10.0, 10.0], 2)
    assert abs(c - 0.0) < 1e-9, c
    # Optimal cost 0 requires [0,0,0] and [10,10] -> boundaries [0,3].
    assert b == [0, 3], b

    # Repeated values, k=1 -> single cluster
    c, b = partition_points([4, 4, 4, 4], 1)
    assert abs(c - 0.0) < 1e-9 and b == [0], (c, b)

    # Repeated values, k=n -> each point its own cluster
    c, b = partition_points([3, 3, 3], 3)
    assert abs(c - 0.0) < 1e-9 and b == [0, 1, 2], (c, b)

    # Mixed repeats with a clear optimum
    c, b = partition_points([1, 1, 1, 2, 2, 2, 10, 10, 10], 3)
    assert abs(c - 0.0) < 1e-9, c
    assert b == [0, 3, 6], b

    # --- Determinism check: repeated calls give identical results ---
    for _ in range(3):
        assert partition_points([0, 2, 4], 2) == (2.0, [0, 1])
        assert partition_points([7, 7, 7, 7, 7], 3)[1] == [0, 1, 2]

    # --- Lex-smallest tie-break is order-independent by construction ---
    # Construct a case with multiple ties across different j levels.
    # x=[0,2,4,6], k=2: t=1 -> [0],[2,4,6] cost 8.0
    #                   t=2 -> [0,2],[4,6] cost 2.0
    #                   t=3 -> [0,2,4],[6] cost 8.0
    # Unique optimum at t=2.
    c, b = partition_points([0, 2, 4, 6], 2)
    assert abs(c - 2.0) < 1e-9 and b == [0, 2], (c, b)

    print("All deterministic self-tests passed (repeats + ties).")
```

## Summary of what is handled and preserved

| Aspect | Status |
|---|---|
| Repeated values | Explicitly tested: all-equal, two-group, `k=1`, `k=n`, mixed repeats. WCSS=0 cases verified. |
| Deterministic ties | Explicitly handled by comparing full candidate boundary lists and keeping the **lexicographically smallest** — no reliance on loop order or `<` vs `<=`. |
| Original outputs | Still returns exactly `(min_cost, boundaries)`. |
| Original tie rule | Lex-smallest boundaries — now enforced directly, not accidentally. |
| Prefix sums + interval-cost DP | Unchanged. |
| Complexity | O(k·n²) time; O(k·n) space (slightly higher constant due to storing boundary lists, still same asymptotic order). |
| Standard library only | Yes. |
| `ValueError` guard | Unchanged. |

The key correction versus the earlier `<=`-with-ascending-`t` version: that version actually produced the **lexicographically largest** boundary list among ties. The corrected version compares full boundary lists explicitly, guaranteeing the documented **lexicographically smallest** result regardless of iteration order.
