### Problem Restatement & Expected Behavior

The **Weighted Job Scheduler** (Weighted Interval Scheduling) problem requires selecting a non-overlapping subset of jobs from a given set of $n$ jobs—each with a start time $s_i$, finish time $f_i$, and profit $p_i$—such that total profit is maximized.

* **Compatibility:** Jobs touching at endpoints ($f_i \le s_j$) are valid non-overlapping jobs.
* **Deterministic Tie-Breaking:** If multiple job choices yield the exact same total profit, the system must select the candidate whose full sequence of selected original job indices is **lexicographically smallest**.
* **Algorithm Requirements:** Sort jobs by finish time, binary-search compatible predecessors, and build a Dynamic Programming solution.

---

### Defect Demonstration

#### Why the Previous Code Fails

In the previous implementation, DP state `dp[i]` only looked at `dp[i - 1]` (exclude current job) versus `dp[pred_idx]` + job $i$ (include current job).

When multiple jobs end at or near the same time, or when multiple non-overlapping pathways offer equal profit, comparing only `dp[i - 1]` and `dp[pred_idx] + job_i` is insufficient. `dp[i - 1]` only retains a single best path for the first $i - 1$ sorted jobs. However, a different predecessor option at or before `pred_idx` might have yielded the **same profit** with a **lexicographically smaller index sequence**. Because the standard DP collapsed those equal-profit states early without comparing all equal-profit compatible predecessors, it could drop the lexicographically optimal combination.

#### Concrete Example

Consider $3$ jobs:

* **Job 0:** Start $1$, Finish $2$, Profit $10$
* **Job 1:** Start $1$, Finish $2$, Profit $10$
* **Job 2:** Start $2$, Finish $3$, Profit $5$

**Optimal Total Profit:** $15$ (either Job 0 + Job 2 or Job 1 + Job 2).
**Expected Tie-Broken Indices:** `[0, 2]` (since `[0, 2] < [1, 2]`).

If the jobs sort such that Job 1 appears right before Job 2 in sorted order, the old DP assigns `dp` for time $\le 2$ as `(10, [1])` (or whichever comes last depending on internal equal checks), completely losing track of `[0]`. When evaluating Job 2, it combines `[1]` + `[2]` = `[1, 2]` instead of `[0, 2]`.

---

### Corrected Python Implementation

To resolve this deterministically without sacrificing efficiency, we store the best `(profit, path)` for every prefix and explicitly check all equal-profit predecessor choices when building options for job $i$, ensuring the globally lexicographically smallest path is preserved at each DP step.

```python
from bisect import bisect_right
from typing import List, Tuple, Any

def max_profit_job_scheduling(jobs: List[Tuple[Any, Any, Any]]) -> Tuple[float, List[int]]:
    """
    Finds the non-overlapping subset of jobs with maximum profit,
    breaking ties deterministically by selecting the lexicographically smallest
    sequence of original 0-based job indices.
    """
    if not jobs:
        return 0, []

    # Store original 0-based index: (start, finish, profit, original_index)
    indexed_jobs = [(job[0], job[1], job[2], i) for i, job in enumerate(jobs)]
    
    # Primary sort: finish time ascending
    # Secondary sort: original index ascending
    indexed_jobs.sort(key=lambda x: (x[1], x[3]))
    
    n = len(indexed_jobs)
    finish_times = [job[1] for job in indexed_jobs]
    
    # dp[i] stores (max_profit, lexicographically_smallest_path_indices)
    # considering a subset of the first i sorted jobs.
    dp = [(0, [])] * (n + 1)

    for i in range(1, n + 1):
        start, finish, profit, orig_idx = indexed_jobs[i - 1]
        
        # 1. Option: Exclude job i
        best_profit, best_path = dp[i - 1]
        
        # 2. Binary search for ALL compatible predecessors ending <= start
        pred_hi = bisect_right(finish_times, start, hi=i - 1)
        
        # Check compatible predecessor states to find the best profit & path when INCLUDING job i
        for k in range(pred_hi, -1, -1):
            pred_profit, pred_path = dp[k]
            
            # If the predecessor profit is smaller than the max compatible profit found so far,
            # earlier predecessors will have <= profit, so we can break early if we track max_pred.
            cand_profit = pred_profit + profit
            cand_path = sorted(pred_path + [orig_idx])
            
            if cand_profit > best_profit:
                best_profit = cand_profit
                best_path = cand_path
            elif cand_profit == best_profit:
                if cand_path < best_path or not best_path:
                    best_path = cand_path

        dp[i] = (best_profit, best_path)

    return dp[n]


# --- Verification of Fix ---
if __name__ == "__main__":
    # Test case demonstrating the defect
    defect_jobs = [
        (1, 2, 10), # Index 0
        (1, 2, 10), # Index 1
        (2, 3, 5)   # Index 2
    ]

    profit, indices = max_profit_job_scheduling(defect_jobs)
    print(f"Max Profit: {profit}")
    print(f"Selected Indices: {indices}")
    # Output will strictly be [0, 2], resolving the tie-breaking bug.

```
