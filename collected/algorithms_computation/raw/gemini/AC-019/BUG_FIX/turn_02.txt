### Problem & Expected Behavior

**Problem:** Given an $M \times N$ matrix of non-negative edge costs, find a path from $(0, 0)$ to $(M-1, N-1)$ moving only right or down that minimizes the total cost.

**Expected Behavior:**

1. Compute the exact minimum path cost.
2. Construct and return a single, deterministic path as a sequence of coordinate tuples $[(0,0), \dots, (M-1, N-1)]$.
3. When multiple paths produce the exact same minimum cost, ties must be broken deterministically at every step using consistent predecessor tracking.

---

### Defect Demonstration

In the previous implementation, when $r > 0$ and `from_up > from_left`, the code assigned:




While this branch correctly set `(r, c - 1)` for $r > 0$, the `if r == 0` check inside a loop starting at `r = 1` was redundant dead logic. More critically, for $r > 0$, if `from_up <= from_left`, it set `parent[r][c] = (r - 1, c)`. However, when inspecting or logging parent steps across subproblems, any inconsistency in direction selection leads to bugs or unintended branching when tie-breaking preferences are evaluated.

Consider the matrix:



* **Path 1 (Right then Down):** $(0,0) \to (0,1) \to (1,1)$ — Cost: $1 + 2 + 1 = 4$
* **Path 2 (Down then Right):** $(0,0) \to (1,0) \to (1,1)$ — Cost: $1 + 1 + 1 = 3$

Path 2 is strictly minimal (cost 3). However, if tied matrices like `[[1, 1], [1, 1]]` are passed:

* `dp[0][1] = 2` (via $(0,0)$)
* `dp[1][0] = 2` (via $(0,0)$)
* For `dp[1][1]`: `from_up = 2` and `from_left = 2`.
* Under `from_up <= from_left`, the tied preference chooses **Up** `(0, 1)`, resulting in path `[(0, 0), (1, 0), (1, 1)]` depending on predecessor reconstruction order.

---

### Corrected Implementation

Here is the clean, bug-free implementation enforcing explicit deterministic tie handling (preferring **Up** over **Left** on equal path costs):

```python
def min_cost_path(matrix):
    """
    Finds the minimum cost path in a grid moving only Right or Down,
    using deterministic tie-breaking (prefers Up over Left predecessor).
    
    Args:
        matrix (List[List[Union[int, float]]]): Non-empty 2D grid of non-negative costs.
        
    Returns:
        Tuple[Union[int, float], List[Tuple[int, int]]]: (minimum_cost, path)
    """
    if not matrix or not matrix[0]:
        return 0, []

    rows = len(matrix)
    cols = len(matrix[0])

    dp = [[0] * cols for _ in range(rows)]
    parent = [[None] * cols for _ in range(rows)]

    # Base case
    dp[0][0] = matrix[0][0]

    # Initialize first column
    for r in range(1, rows):
        dp[r][0] = dp[r - 1][0] + matrix[r][0]
        parent[r][0] = (r - 1, 0)

    # Initialize first row
    for c in range(1, cols):
        dp[0][c] = dp[0][c - 1] + matrix[0][c]
        parent[0][c] = (0, c - 1)

    # Fill DP table with explicit, consistent tie-breaking
    for r in range(1, rows):
        for c in range(1, cols):
            from_up = dp[r - 1][c]
            from_left = dp[r][c - 1]

            # Deterministic tie-handling rule: Prefer Up over Left when costs match
            if from_up <= from_left:
                dp[r][c] = matrix[r][c] + from_up
                parent[r][c] = (r - 1, c)
            else:
                dp[r][c] = matrix[r][c] + from_left
                parent[r][c] = (r, c - 1)

    # Backtrack from bottom-right to top-left
    path = []
    curr = (rows - 1, cols - 1)
    while curr is not None:
        path.append(curr)
        curr = parent[curr[0]][curr[1]]

    path.reverse()
    return dp[rows - 1][cols - 1], path

```
