### Problem & Expected Behavior Restatement

Given a set of coin denominations $C$ and a target amount $A$:

* **Goal:** Find the minimum number of coins that sum to $A$. If impossible, return `(-1, [])`.
* **Expected Result:** Return a tuple `(min_coins, combination)` where `combination` is the specific multiset of coin values sorted in non-decreasing order.
* **Deterministic Tie-Handling Rule:** When multiple distinct combinations yield the **same minimum coin count**, the dynamic programming transitions must resolve ties deterministically (e.g., consistently selecting the combination that forms a lexicographically smallest sequence of sorted coins).

---

### Defect Demonstration

In the previous implementation:


The inner loop only updates `parent[i]` when `dp[i - coin] + 1 < dp[i]` (a strict inequality). When two distinct choices yield the **same minimal coin count**, the code keeps whichever coin appeared first in `coins` during iteration, completely ignoring the coin choices made earlier in the reconstructed path (`dp[i - coin]`).

#### Example Counterexample:

Consider `coins = [1, 3, 4]` and `amount = 6`:

* **Valid 2-coin combinations for 6:** `[3, 3]` and `[2 choices: (1, 5) impossible, but (3, 3) vs (2, 4)? No, 2 isn't in set]`. Wait, `[3, 3]` uses 2 coins. `[1, 5]` is invalid. `[4, 1, 1]` uses 3 coins.
Let's consider `coins = [2, 3, 5]` and `amount = 8`:
* `[3, 5]` uses 2 coins (sorted: `[3, 5]`).
* `[2, 3, 3]` uses 3 coins.
Let's look at `coins = [1, 3, 4]` and `amount = 6`:
* `6 = 3 + 3` (2 coins: `[3, 3]`)
* `6 = 2 + 4` (Not possible with 1,3,4)

Let's test `coins = [1, 3, 4]` and `amount = 6`:
To get `6`:

* `dp[6] = 2` via `3 + 3` (`[3, 3]`).
Is there another combination? No.

Let's test `coins = [2, 3, 5, 6]` and `amount = 8`:

* `8 = 3 + 5` $\rightarrow$ `[3, 5]` (2 coins)
* `8 = 2 + 6` $\rightarrow$ `[2, 6]` (2 coins)

Both `[2, 6]` and `[3, 5]` use **2 coins**.
Lexicographically, `[2, 6]` is strictly smaller than `[3, 5]`.

With the buggy implementation where `coins = [2, 3, 5, 6]`:

* For $i = 8$:
* Try coin `2`: `dp[8 - 2] + 1` = `dp[6] + 1`. `6` is optimal as `3 + 3` (2 coins, `[3, 3]`). Total path for coin 2: `[2, 3, 3]` (3 coins).
* Try coin `3`: `dp[8 - 3] + 1` = `dp[5] + 1`. `dp[5] = 1` (`5`). Total coins = $1 + 1 = 2$. Path: `[3, 5]`. `dp[8]` becomes `2`, `parent[8] = 3`.
* Try coin `6`: `dp[8 - 6] + 1` = `dp[2] + 1`. `dp[2] = 1` (`2`). Total coins = $1 + 1 = 2$. Strict inequality `2 < 2` is **False**, so `parent[8]` remains `3`.


* Result produced: `[3, 5]`
* Deterministic canonical output expected: `[2, 6]` (because `[2, 6] < [3, 5]` lexicographically).

---

### Corrected Implementation

To enforce deterministic tie-breaking across equal-length paths, we store the actual optimal sorted sub-combination (or a canonical tuple representation) in the DP array so that ties in coin count can be broken lexicographically.

```python
from typing import List, Tuple

def min_coin_change(coins: List[int], amount: int) -> Tuple[int, List[int]]:
    if amount == 0:
        return 0, []
    if amount < 0 or not coins:
        return -1, []

    # Sort and remove duplicates from coin denominations
    unique_coins = sorted(list(set(coins)))

    # dp[i] will store a tuple: (coin_count, canonical_combination_list)
    # Target value initialized to infinity
    inf = float('inf')
    dp = [(inf, []) for _ in range(amount + 1)]
    dp[0] = (0, [])

    for i in range(1, amount + 1):
        best_count = inf
        best_comb = None

        for coin in unique_coins:
            if i - coin >= 0:
                prev_count, prev_comb = dp[i - coin]
                if prev_count != inf:
                    candidate_count = prev_count + 1
                    # Candidate path sorted deterministically
                    candidate_comb = sorted(prev_comb + [coin])

                    if candidate_count < best_count:
                        best_count = candidate_count
                        best_comb = candidate_comb
                    elif candidate_count == best_count:
                        # Tie-breaking: Choose lexicographically smaller sorted combination
                        if best_comb is None or candidate_comb < best_comb:
                            best_comb = candidate_comb

        if best_comb is not None:
            dp[i] = (best_count, best_comb)

    count, combination = dp[amount]
    if count == inf:
        return -1, []

    return count, combination


if __name__ == "__main__":
    # Test demonstrating fix for tie-handling
    coins = [2, 3, 5, 6]
    target = 8
    count, combination = min_coin_change(coins, target)
    print(f"Target: {target}")
    print(f"Minimum Coins: {count}")
    print(f"Coins Used (Canonical Lexicographical Tie-Breaker): {combination}")

```
