# Problem restatement — Mutable Range Sum Engine

Maintain an integer array under two operations, processed in sequence order:

1. **Point replacement** — set the value at a given index to a new value.
2. **Range sum query** — return the inclusive sum over `[l, r]`, reflecting all updates applied so far.

**Required outputs (unchanged throughout):**
- A list of integers, one per range-sum query, in the order the queries were issued (or, when the summary feature is requested, `{"results": [...], "operation_summary": {...}}` with `results` identical to the plain-mode list).
- Deterministic tie handling: `left == right` is a valid single-element query; `left > right` raises `ValueError`; `update` always keeps the shadow array in sync even when the new value equals the old one.
- Index bounds validated; out-of-range indices raise `IndexError`.
- O(log n) per operation via a Fenwick tree; pure standard library — no randomness, network access, external services, or human interaction.

The implementation itself (`FenwickTree`, `ArrayWithRangeSum`, `process_operations`) is **unchanged** from the previous turn. Below I add the worst-case/difficult-case tests requested, plus a brute-force cross-check, without touching the engine's behavior or output contract.

## Difficult / worst-case cases to cover

1. **Maximum Fenwick chain length** — updating index `0` in an array whose size `n` is a power of two forces the update loop to touch `log2(n)+1` nodes (the theoretical worst case for `add`), and querying `prefix_sum(n-1)` forces the same worst case for the read loop.
2. **Repeated writes to the same index**, including a **zero-delta replacement** (new value equals current value) sandwiched between real changes — must not desync the shadow array or double-count in the summary.
3. **Boundary ties** — `query(0, 0)` and `query(n-1, n-1)` on a large array (leftmost/rightmost single-element ranges).
4. **Full-range query** `[0, n-1]` after a long, deterministic sequence of interleaved updates and queries — cross-checked against a brute-force list-based reference (no `random` module; indices/values generated by a deterministic linear-congruential-style formula).
5. **Minimum size** `n = 1`.
6. **Large-magnitude and negative values**, to confirm no overflow/precision issues (Python ints are arbitrary precision, but this checks sign handling in deltas).
7. **Invalid tie** `left > right` (e.g., `query(5, 4)`) must still raise, even inside a stress sequence.

```python
class FenwickTree:
    """Binary Indexed Tree supporting point updates and prefix-sum queries in O(log n)."""

    __slots__ = ("n", "tree", "_count_ops", "update_node_touches", "query_node_touches")

    def __init__(self, n: int, count_ops: bool = False):
        self.n = n
        self.tree = [0] * (n + 1)  # 1-indexed internally
        self._count_ops = count_ops
        self.update_node_touches = 0
        self.query_node_touches = 0

    def add(self, index: int, delta: int) -> None:
        i = index + 1
        while i <= self.n:
            self.tree[i] += delta
            if self._count_ops:
                self.update_node_touches += 1
            i += i & (-i)

    def prefix_sum(self, index: int) -> int:
        if index == -1:
            return 0
        if index < -1:
            raise ValueError(f"invalid prefix index: {index}")
        i = index + 1
        total = 0
        while i > 0:
            total += self.tree[i]
            if self._count_ops:
                self.query_node_touches += 1
            i -= i & (-i)
        return total

    def range_sum(self, left: int, right: int) -> int:
        if left > right:
            raise ValueError(f"invalid range: left={left} > right={right}")
        return self.prefix_sum(right) - self.prefix_sum(left - 1)


class ArrayWithRangeSum:
    """
    Maintains an integer array under point replacement and inclusive
    range-sum queries, backed by a Fenwick tree, with deterministic
    handling of tie/boundary cases and optional operation counting.
    """

    def __init__(self, initial: list, track_summary: bool = False):
        self.n = len(initial)
        self.values = list(initial)
        self.track_summary = track_summary
        self.tree = FenwickTree(self.n, count_ops=track_summary)
        self.updates_processed = 0
        self.queries_processed = 0
        for idx, val in enumerate(initial):
            if val != 0:
                self.tree.add(idx, val)
        if track_summary:
            self.tree.update_node_touches = 0
            self.tree.query_node_touches = 0

    def _check_index(self, index: int) -> None:
        if not isinstance(index, int) or not (0 <= index < self.n):
            raise IndexError(f"index {index} out of bounds for array of size {self.n}")

    def update(self, index: int, new_value: int) -> None:
        self._check_index(index)
        delta = new_value - self.values[index]
        self.values[index] = new_value
        if delta != 0:
            self.tree.add(index, delta)
        if self.track_summary:
            self.updates_processed += 1

    def query(self, left: int, right: int) -> int:
        self._check_index(left)
        self._check_index(right)
        if left > right:
            raise ValueError(f"invalid range: left={left} > right={right}")
        result = self.tree.range_sum(left, right)
        if self.track_summary:
            self.queries_processed += 1
        return result

    def summary(self) -> dict:
        return {
            "updates_processed": self.updates_processed,
            "queries_processed": self.queries_processed,
            "fenwick_update_node_touches": self.tree.update_node_touches,
            "fenwick_query_node_touches": self.tree.query_node_touches,
            "total_fenwick_node_touches": (
                self.tree.update_node_touches + self.tree.query_node_touches
            ),
        }


def process_operations(initial: list, operations: list, include_summary: bool = False):
    structure = ArrayWithRangeSum(initial, track_summary=include_summary)
    results = []
    for op in operations:
        kind = op[0]
        if kind == "update":
            _, index, new_value = op
            structure.update(index, new_value)
        elif kind == "query":
            _, left, right = op
            results.append(structure.query(left, right))
        else:
            raise ValueError(f"unknown operation type: {kind}")

    if not include_summary:
        return results
    return {
        "results": results,
        "operation_summary": structure.summary(),
    }


# --------------------------------------------------------------------------
# Deterministic pseudo-sequence generator (NOT the random module).
# A simple linear-congruential recurrence, seeded and iterated by hand,
# so the same call always produces the same sequence.
# --------------------------------------------------------------------------
def _lcg_stream(seed: int, count: int):
    """Yield `count` deterministic pseudo-values from a fixed LCG."""
    state = seed
    a, c, m = 1103515245, 12345, 2 ** 31
    out = []
    for _ in range(count):
        state = (a * state + c) % m
        out.append(state)
    return out


def _brute_force_reference(initial, operations):
    """Simple O(n) list-based reference implementation for cross-checking."""
    arr = list(initial)
    n = len(arr)
    results = []
    for op in operations:
        kind = op[0]
        if kind == "update":
            _, index, new_value = op
            if not (0 <= index < n):
                raise IndexError("index out of bounds")
            arr[index] = new_value
        else:
            _, left, right = op
            if not (0 <= left < n) or not (0 <= right < n):
                raise IndexError("index out of bounds")
            if left > right:
                raise ValueError("invalid range")
            results.append(sum(arr[left:right + 1]))
    return results


def _ceil_log2(n: int) -> int:
    bits = 0
    v = 1
    while v < n:
        v <<= 1
        bits += 1
    return bits


if __name__ == "__main__":
    # --- Original functional test (unchanged behavior) ---------------------
    base_array = [1, 3, 5, 7, 9, 11]
    ops = [
        ("query", 1, 3),
        ("update", 1, 10),
        ("query", 1, 3),
        ("update", 4, 0),
        ("query", 0, 5),
        ("query", 2, 2),
    ]
    plain = process_operations(base_array, ops)
    assert plain == [15, 22, 34, 5], f"Original contract broken: {plain}"

    full = process_operations(base_array, ops, include_summary=True)
    assert full["results"] == [15, 22, 34, 5]
    assert full["operation_summary"]["updates_processed"] == 2
    assert full["operation_summary"]["queries_processed"] == 4

    # --- Case 1: maximum Fenwick chain length (n a power of two) -----------
    n_pow2 = 1024  # 2^10
    arr_pow2 = [0] * n_pow2
    structure = ArrayWithRangeSum(arr_pow2, track_summary=True)
    structure.update(0, 5)                     # worst case for `add`
    structure.query(0, n_pow2 - 1)              # worst case for `prefix_sum`
    expected_max_touches = _ceil_log2(n_pow2) + 1
    assert structure.tree.update_node_touches <= expected_max_touches, (
        structure.tree.update_node_touches, expected_max_touches
    )
    assert structure.tree.query_node_touches <= expected_max_touches, (
        structure.tree.query_node_touches, expected_max_touches
    )
    assert structure.query(0, n_pow2 - 1) == 5

    # --- Case 2: repeated writes to same index, including zero-delta -------
    small = [10, 20, 30]
    ops_repeat = [
        ("update", 1, 99),
        ("update", 1, 99),   # zero-delta replacement: must not desync/undercount
        ("query", 0, 2),     # 10 + 99 + 30 = 139
        ("update", 1, 20),   # restore original value
        ("query", 1, 1),     # tie: single element -> 20
    ]
    res_repeat = process_operations(small, ops_repeat, include_summary=True)
    assert res_repeat["results"] == [139, 20], res_repeat["results"]
    assert res_repeat["operation_summary"]["updates_processed"] == 3
    assert res_repeat["operation_summary"]["queries_processed"] == 2

    # --- Case 3: boundary ties on a large array -----------------------------
    n_big = 5000
    arr_big = list(range(n_big))  # deterministic, non-random content
    struct_big = ArrayWithRangeSum(arr_big)
    assert struct_big.query(0, 0) == 0
    assert struct_big.query(n_big - 1, n_big - 1) == n_big - 1

    # --- Case 4: long deterministic interleaved sequence vs brute force -----
    n_stress = 500
    op_count = 3000
    init_stress = _lcg_stream(seed=42, count=n_stress)
    init_stress = [v % 1000 - 500 for v in init_stress]  # include negatives

    stream = _lcg_stream(seed=7, count=op_count * 3)
    stress_ops = []
    for i in range(op_count):
        a, b, c = stream[3 * i], stream[3 * i + 1], stream[3 * i + 2]
        if a % 2 == 0:
            idx = b % n_stress
            val = (c % 2001) - 1000  # deterministic value in [-1000, 1000]
            stress_ops.append(("update", idx, val))
        else:
            l = b % n_stress
            r = c % n_stress
            if l > r:
                l, r = r, l  # keep this batch of generated ops valid
            stress_ops.append(("query", l, r))

    fast_result = process_operations(init_stress, stress_ops)
    slow_result = _brute_force_reference(init_stress, stress_ops)
    assert fast_result == slow_result, "Fenwick engine diverged from brute-force reference"

    # Full-range query after the stress sequence must also match brute force
    stress_ops_full = stress_ops + [("query", 0, n_stress - 1)]
    assert (
        process_operations(init_stress, stress_ops_full)[-1]
        == _brute_force_reference(init_stress, stress_ops_full)[-1]
    )

    # --- Case 5: minimum size n = 1 ------------------------------------------
    single = [42]
    assert process_operations(single, [("query", 0, 0)]) == [42]
    single_ops = [("update", 0, -7), ("query", 0, 0)]
    assert process_operations(single, single_ops) == [-7]

    # --- Case 6: large-magnitude and negative values --------------------------
    magnitude_arr = [10 ** 12, -(10 ** 12), 5]
    magnitude_ops = [
        ("query", 0, 2),               # 10^12 - 10^12 + 5 = 5
        ("update", 0, -(10 ** 15)),
        ("query", 0, 1),               # -10^15 - 10^12
    ]
    mag_result = process_operations(magnitude_arr, magnitude_ops)
    assert mag_result == [5, -(10 ** 15) - 10 ** 12], mag_result

    # --- Case 7: invalid tie (left > right) must still raise ------------------
    try:
        process_operations(small, [("query", 2, 0)])
        raised = False
    except ValueError:
        raised = True
    assert raised, "left > right must raise ValueError, even in isolation"

    print("All original, feature, and worst-case tests passed.")
```

**What this adds, and what it deliberately leaves untouched:**
- No change to `FenwickTree`, `ArrayWithRangeSum`, or `process_operations` — same output shapes, same exceptions, same tie rules (`left == right` valid, `left > right` raises, zero-delta updates still sync the shadow array).
- New deterministic stress generator (`_lcg_stream`) replaces any need for `random`: same seed always produces the same operation sequence, satisfying the no-randomness constraint while still exercising a large, varied, hard-to-hand-craft workload.
- `_brute_force_reference` gives an independent O(n)-per-query oracle to cross-validate the Fenwick tree's correctness under the stress sequence, including negative values and large magnitudes.
- Worst-case chain-length assertions (`_ceil_log2`) directly verify the stated O(log n) complexity bound is respected at the structural level, not just empirically fast.
