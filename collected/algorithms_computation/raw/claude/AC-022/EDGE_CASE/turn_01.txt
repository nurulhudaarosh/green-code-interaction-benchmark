# Problem Identification

**Task:** Given two strings `s` and `t`, compute the minimum number of edit operations to turn `s` into `t`.

**Allowed operations (each cost 1):**
1. Insertion of a character
2. Deletion of a character
3. Substitution of one character for another
4. Transposition of two *adjacent* characters

**Output:** A single non-negative integer, the minimum total cost.

## Key Constraints and Subtleties

- **Which variant?** With transposition costing 1, there are two well-known measures:
  - *Optimal String Alignment (OSA)*, also called restricted edit distance: no substring is edited more than once. It can overestimate, e.g. `"CA" → "ABC"` gives 3 under OSA.
  - *True Damerau-Levenshtein*: allows edits between a transposed pair (e.g. inserting a character between the swapped letters). `"CA" → "ABC"` gives 2.
- The problem says "edit distance using ... adjacent transposition" with no restriction, so the **true** minimum over all edit sequences is the correct target. I implement true Damerau-Levenshtein, which handles the interleaved case.
- Strings may be empty; the answer is then the other string's length.
- Characters can be any hashable Unicode characters (work on `str` code points).
- Complexity target: O(n·m) time and space, which is fine for typical sizes.

## Algorithm

Use dynamic programming with an explicit transposition transition (Lowrance–Wagner):

- `d[i][j]` = distance between `s[:i]` and `t[:j]`.
- Base: `d[i][0] = i`, `d[0][j] = j`.
- Standard transitions: deletion `d[i-1][j]+1`, insertion `d[i][j-1]+1`, substitution/match `d[i-1][j-1] + (s[i-1] != t[j-1])`.
- **Transposition transition:** let `i1 = last[t[j-1]]` be the last row in `s` (before `i`) where character `t[j-1]` appeared, and `j1` the last column in `t` (before `j`) where `s[i-1]` matched. If both exist, the candidate is
  `d[i1-1][j1-1] + (i - i1 - 1) + 1 + (j - j1 - 1)`
  i.e. reach the state before the swapped pair, delete the characters in between in `s`, do one swap, then insert the characters in between in `t`.
- The answer is `d[n][m]`.

## Implementation

```python
def edit_distance(s: str, t: str) -> int:
    """True Damerau-Levenshtein distance: insert, delete, substitute,
    and adjacent transposition, each with cost 1."""
    n, m = len(s), len(t)
    if n == 0:
        return m
    if m == 0:
        return n

    # last_row[c] = last row index (1-based) in s where character c occurred
    last_row = {}

    # d has an extra border row/column to simplify the transposition lookup.
    # Use offset 1: D[i+1][j+1] corresponds to distance(s[:i], t[:j]).
    INF = n + m
    D = [[0] * (m + 2) for _ in range(n + 2)]
    D[0][0] = INF
    for i in range(n + 1):
        D[i + 1][0] = INF
        D[i + 1][1] = i
    for j in range(m + 1):
        D[0][j + 1] = INF
        D[1][j + 1] = j

    for i in range(1, n + 1):
        last_match_col = 0  # last column j in t where s[i-1] == t[j-1]
        for j in range(1, m + 1):
            i1 = last_row.get(t[j - 1], 0)
            j1 = last_match_col

            if s[i - 1] == t[j - 1]:
                cost = 0
                last_match_col = j
            else:
                cost = 1

            D[i + 1][j + 1] = min(
                D[i][j] + cost,          # substitution / match
                D[i + 1][j] + 1,         # insertion
                D[i][j + 1] + 1,         # deletion
                # transposition (with optional in-between deletions/insertions)
                D[i1][j1] + (i - i1 - 1) + 1 + (j - j1 - 1),
            )

        last_row[s[i - 1]] = i

    return D[n + 1][m + 1]


if __name__ == "__main__":
    tests = [
        ("", "", 0),
        ("", "abc", 3),
        ("abc", "", 3),
        ("abc", "abc", 0),
        ("ab", "ba", 1),          # one transposition
        ("abcd", "acbd", 1),      # adjacent swap
        ("kitten", "sitting", 3), # classic Levenshtein case
        ("ca", "abc", 2),         # true DL (OSA would give 3)
        ("a", "b", 1),
        ("abcdef", "abcfed", 3),
    ]
    for a, b, expected in tests:
        got = edit_distance(a, b)
        status = "OK" if got == expected else "FAIL"
        print(f"{status}: edit_distance({a!r}, {b!r}) = {got} (expected {expected})")
        assert got == expected
```

## Notes

- **Deterministic:** pure computation, no randomness, I/O beyond printing test results, or external dependencies (standard library only; none are even imported).
- **Complexity:** O(n·m) time, O(n·m) space (plus O(σ) for the `last_row` dictionary, σ = alphabet size actually used).
- **Why the extra border:** the transposition lookup may reference row/column index 0 (meaning "no previous occurrence"), which maps to `D[0][*]`/`D[*][0]` set to `INF`, so that candidate is automatically ignored when no valid swap exists.
- If you instead want the simpler restricted (OSA) variant, replace the transposition term with `d[i-2][j-2] + 1` guarded by `s[i-1]==t[j-2] and s[i-2]==t[j-1]`; it is easier but gives larger results on cases like `"ca" → "abc"`.
