## Problem

Given an undirected weighted graph with `n` vertices and `m` edges, and a list of thresholds `q`, answer each query using only the edges with weight `<= q`. Each answer is:

1. the number of connected components, and
2. the size of the largest component.

## Key constraints and assumptions

- Vertices are numbered `0..n-1`. Isolated vertices count as components of size 1.
- Edges are `(u, v, w)`. Self-loops and parallel edges are allowed and harmless.
- Queries may repeat or arrive in any order, so answers must be returned in the original query order.
- `n`, `m` and the number of queries may be large, so a naive per-query rebuild at O(k·(n+m)) is too slow. The solution works offline and avoids recursion, so deep trees don't hit the recursion limit.

## Output

A list with one `(components, largest_size)` tuple per query, in input order.

## Algorithm

1. Sort the edges by weight.
2. Sort the query indices by threshold.
3. Sweep through the queries in increasing threshold order. Before answering a query, union every not-yet-added edge with `w <= q` using a disjoint-set union (union by size plus path compression).
4. Maintain the component count (starts at `n`, drops by 1 on each successful union) and the maximum component size (updated on each union).
5. Record the current `(count, max_size)` at the query's original index.

Complexity: O((m + k) log(m + k) + (m + k)·α(n)).

## Implementation

```python
from typing import List, Tuple


def components_by_threshold(
    n: int,
    edges: List[Tuple[int, int, int]],
    queries: List[int],
) -> List[Tuple[int, int]]:
    """For each q, return (number_of_components, largest_component_size)
    using only edges with weight <= q. Deterministic, stdlib only."""
    parent = list(range(n))
    size = [1] * n

    def find(x: int) -> int:
        root = x
        while parent[root] != root:
            root = parent[root]
        while parent[x] != root:          # path compression (iterative)
            parent[x], x = root, parent[x]
        return root

    sorted_edges = sorted(edges, key=lambda e: e[2])
    order = sorted(range(len(queries)), key=lambda i: queries[i])

    comps = n
    largest = 1 if n > 0 else 0
    ei = 0
    m = len(sorted_edges)
    answers: List[Tuple[int, int]] = [(0, 0)] * len(queries)

    for qi in order:
        q = queries[qi]
        while ei < m and sorted_edges[ei][2] <= q:
            u, v, _ = sorted_edges[ei]
            ei += 1
            ru, rv = find(u), find(v)
            if ru != rv:
                if size[ru] < size[rv]:
                    ru, rv = rv, ru
                parent[rv] = ru
                size[ru] += size[rv]
                comps -= 1
                if size[ru] > largest:
                    largest = size[ru]
        answers[qi] = (comps, largest)

    return answers


if __name__ == "__main__":
    n = 5
    edges = [(0, 1, 1), (1, 2, 3), (3, 4, 2), (2, 3, 5)]
    queries = [0, 1, 2, 3, 5]
    print(components_by_threshold(n, edges, queries))
    # [(5, 1), (4, 2), (3, 2), (2, 3), (1, 5)]
```

The demo output is fixed, since the code uses no randomness, I/O, or network access. For `q=3`, edges `0-1`, `3-4` and `1-2` are active, giving components `{0,1,2}` and `{3,4}`, so 2 components with largest size 3.
