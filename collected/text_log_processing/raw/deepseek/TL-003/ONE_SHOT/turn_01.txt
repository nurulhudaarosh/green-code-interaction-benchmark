Here's a clean implementation of `dedup_lines`:

```python
def dedup_lines(in_path, out_path, mode='exact'):
    """
    Remove duplicate lines from a file, keeping first occurrences in order.

    Args:
        in_path:  Path to the input file.
        out_path: Path to the output file.
        mode:     'exact' (default) compares raw lines without trailing newline;
                  'normalized' compares ' '.join(line.strip().lower().split()).

    Returns:
        dict with keys 'total', 'unique', 'removed'.
    """
    if mode not in ('exact', 'normalized'):
        raise ValueError("mode must be 'exact' or 'normalized'")

    seen = set()
    total = 0
    unique = 0

    with open(in_path, 'r', encoding='utf-8', newline='') as fin, \
         open(out_path, 'w', encoding='utf-8', newline='') as fout:

        for raw in fin:
            total += 1

            # Strip only the trailing newline (and any \r before it) for 'exact'
            # so we don't accidentally mutate meaningful whitespace.
            line = raw
            if line.endswith('\n'):
                line = line[:-1]
                if line.endswith('\r'):
                    line = line[:-1]

            if mode == 'normalized':
                key = ' '.join(line.strip().lower().split())
            else:
                key = line

            if key in seen:
                continue

            seen.add(key)
            unique += 1
            fout.write(line + '\n')

    return {
        'total': total,
        'unique': unique,
        'removed': total - unique,
    }
```

### How it works

1. **Streaming**: Iterates over the input file one line at a time, so memory scales with the number of *unique* lines, not the file size.
2. **Key selection**:
   - `exact`: uses the line with only its trailing `\n` (and optional `\r`) removed — nothing else is altered.
   - `normalized`: collapses internal runs of whitespace and lowercases, matching `' '.join(line.strip().lower().split())`.
3. **Order preserved**: The first time a key is seen, the *original* line (not the normalized form) is written out.
4. **Trailing newline**: The output always ends with `\n` if at least one line was written, and is empty if the input was empty. Input without a final newline is handled correctly because iteration still yields the last partial line.
5. **Newline handling**: Opening with `newline=''` disables universal-newline translation on read, so we control exactly what gets stripped and written.

# input.txt:
#   Hello
#   hello
#   Hello
#   world

dedup_lines('input.txt', 'out_exact.txt', mode='exact')
# -> {'total': 4, 'unique': 3, 'removed': 1}

dedup_lines('input.txt', 'out_norm.txt', mode='normalized')
# -> {'total': 4, 'unique': 2, 'removed': 2}
```

### Edge cases covered

- **Empty file** → all counts are 0, output is empty.
- **No trailing newline** on last line → still deduplicated and written with a trailing newline.
- **Windows line endings (`\r\n`)** → `\r` is stripped along with `\n` in `exact` mode.
- **Blank/whitespace-only lines** → preserved as distinct entries in `exact` mode; collapse to `''` in `normalized` mode (so all blank-ish lines become one).
