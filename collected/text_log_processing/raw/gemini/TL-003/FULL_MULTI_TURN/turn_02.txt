The two bugs in line-counting scripts typically stem from:

1. **Missing trailing newline at EOF:** Using `rstrip('\r\n')` indiscriminately collapses genuine trailing whitespace (like tabs/spaces), while treating a final line lacking `\n` as identical to one that had it—or losing precision on leading/trailing spaces across occurrences.
2. **Whitespace stripping / collapsing:** In standard `rstrip()`, lines like `"hello "` and `"hello"` collide or get mutated depending on where stripping happens, and lines containing only whitespace (e.g. `" "`) get completely emptied.

Here is the robust implementation:

```python
import sys
from collections import Counter

def deduplicate_with_counts(input_stream, output_stream):
    """
    Counts exact duplicate lines (preserving all spaces, tabs, and indentation)
    while normalizing standard line terminators (\\r\\n, \\r, \\n, or EOF without newline).
    """
    counts = Counter()

    for line in input_stream:
        # Strip ONLY the line terminator characters from the end,
        # preserving all intentional trailing spaces, tabs, and content.
        if line.endswith('\r\n'):
            line_body = line[:-2]
        elif line.endswith(('\n', '\r')):
            line_body = line[:-1]
        else:
            # Handles final line at EOF without a trailing newline
            line_body = line

        counts[line_body] += 1

    for line_body, count in counts.items():
        output_stream.write(f"{count:>7} {line_body}\n")

if __name__ == "__main__":
    deduplicate_with_counts(sys.stdin, sys.stdout)

```

### What this fixes

| Scenario | Naive `rstrip()` | Fixed Implementation |
| --- | --- | --- |
| **Trailing whitespace** (`"val  \n"`) | Strips to `"val"`, incorrectly grouping with `"val\n"` | Preserves `"val  "`, distinguishes it from `"val"` |
| **Whitespace-only line** (`"   \n"`) | Collapses to `""` (empty string) | Preserves `"   "` as distinct from a truly blank line |
| **No trailing newline at EOF** (`"val"`) | Handled, but often collided or caused malformed output | Slices exact line endings without stripping payload text; correctly counts with prior `"val\n"` |
| **Mixed line endings** (`\r\n` vs `\n`) | Reliably strips the 1 or 2 terminator bytes without touching the actual content |  |
