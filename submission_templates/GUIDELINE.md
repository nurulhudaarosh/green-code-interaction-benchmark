# 🌱 Green Code Interaction Benchmark
## Complete Member Guideline

> **Read this file once from top to bottom before starting.**
>
> After reading this guide, you should be able to complete and submit tasks without additional instructions.

---

## 1. What You Are Doing

You are helping collect code-generation results for the **Green Code Interaction Benchmark**.

For each assigned task, you will use the same task prompt with four AI models:

- **GPT**
- **Claude**
- **Gemini**
- **DeepSeek**

Each task may contain one or more interaction types. The exact interaction types are defined inside the dataset.

Your job is:

```text
Dataset
   ↓
Copy the exact prompt
   ↓
Run it with GPT / Claude / Gemini / DeepSeek
   ↓
Save the generated code in the provided files
   ↓
Run submit
   ↓
Upload the generated ZIP to the project bot
```

You are **not** responsible for:

- correctness testing
- runtime measurement
- memory measurement
- energy measurement
- RAPL measurement
- result analysis

Those are handled later by the project runner.

Open **Command Prompt** in your workspace folder.

# 9. ONE_SHOT

If the task contains:

```text
ONE_SHOT
```

find the `ONE_SHOT` prompt in:

```text
dataset/<category>/dataset.json
```

Copy that prompt exactly and give it to the model.

Save the generated code in:

```text
<model>/one_shot/code.py
```

Example:

```text
gpt/one_shot/code.py
```

### Important

The `.py` file should contain **only the generated source code**.

Do not save:

```text
Here is the solution:
```python
...
```
```

Instead save:

```python
def build_index(docs):
    ...
```

# 10. BUG_FIX

If the task contains:

```text

```

there will normally be:

```text

```

Save the generated code as:

```text

```

Continue the **same conversation**.

Give the `bug_report` to the same model.

Save the updated code as:

```text
<model>/bug_fix/final.py
```

### Do not

- start a new conversation for Step 2
- manually fix the code
- manually optimize the code

# 13. FULL_MULTI_TURN

This is the most important interaction type.

If the dataset contains:

```text
FULL_MULTI_TURN
```

you must use **one continuous conversation** with the same model.

For example:

```text
Turn 1 → initial task
Turn 2 → bug report
Turn 3 → feature request
Turn 4 → edge case
```

Save the generated versions as:

```text
full_multi_turn/
├── turn_01.py
├── turn_02.py
├── turn_03.py
├── turn_04.py
└── final.py
```

### Rules

Do not:

- start a new chat between turns
- switch models
- manually modify the code
- skip a turn

`final.py` must contain the final code after all required turns.

---

# 14. What Goes Inside `.py` Files?

Only source code.

Correct:

```python
def search(index, query):
    ...
```

Incorrect:

```text
Here is my final answer:

```python
def search(index, query):
    ...
```

Hope this helps!
```

If the model returns Markdown code fences, remove the Markdown fences and save the actual code.

Do not change the code itself.

---

# 15. Do Not Manually Modify Generated Code

You must preserve the model output.

Do not:

- fix syntax errors yourself
- optimize the algorithm
- remove unused code
- add comments
- change variable names
- change formatting for performance
- add libraries
- rewrite the solution

If the model generates bad code, **that is part of the experimental result**.

Save it as generated.

# 26. If Something Goes Wrong

### `sc.bat init` fails

Do not delete the dataset.

Check:

```bat
sc.bat status
```

If it still fails, contact the project administrator and provide the exact error message.

### `sc.bat submit` fails

Read the error carefully.

It will normally tell you which file is missing or empty.

Example:

```text
Missing or empty:
submission/gpt/bug_fix/final.py
```

Create/fill the required file and run:

```bat
sc.bat submit
```

again.

### Bot rejects the ZIP

Do not modify the ZIP manually.

Read the bot's error message and correct the original submission folder if needed.
